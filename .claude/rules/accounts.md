# Claude 계정·사용량

사용량 조회와 상태 표시줄 사용량 창, Claude 계정 보관·전환·로그인·로그아웃(서버·화면)을 다룬다. 계정 기능 시험 규칙은 루트 CLAUDE.md 에 있다.

원래 루트 `CLAUDE.md` 한 파일이던 내용을 옮긴 것이다. 본문의 "위·아래 …"·"핵심 개념 …" 은 그때의 말이라 가리키는 항목이 다른 파일에 있을 수 있다. 어디서나 지킬 규칙·근무·휴식·퇴근·표시 상태·실행 방법은 루트 `CLAUDE.md`, 다른 영역은 루트의 문서 지도를 본다. 이 영역을 고치면 이 파일의 그 줄을 고쳐 쓴다.

다른 파일에 있는 항목:
- 바쁨(`isBusy`)이 보는 표시 상태 → 루트 CLAUDE.md

## 구조

- `server/src/usage.ts` — 계정 사용량(5시간·주간 한도) 조회. `~/.claude/.credentials.json` 의 OAuth 토큰으로 `api.anthropic.com/api/oauth/usage` 호출 (`/usage` 명령과 같은 데이터, 비공식). `GET /api/usage`, 60초 캐시 (화면 ↻ 도 캐시 안이면 같은 값). 한도마다 짧은 이름 `label`(session `5h`, weekly_all `wk`, 모델별 주간은 모델 표시 이름만 예 `Fable`, 그 밖은 kind 그대로)과 한도 종류 `kind`·모델 표시 이름 `model`(아니면 null)을 같이 준다 — 상세 창의 한도 이름은 화면이 kind·model 로 정한다. 응답 `usage` 에는 요금제 `plan`(credentials 의 `subscriptionType`. `rateLimitTier` 끝이 `_<숫자>x` 면 배수를 붙여 `max 5x`·`max 20x`(`planOf`), 화면은 첫 글자만 대문자로 "Max 5x")과 로그인 계정 이메일 `email` 도 있다: Claude Code 가 쓰는 `~/.claude.json` 의 `oauthAccount.emailAddress` 를 **읽기만** 하고(`readAccountEmail`. 이 파일은 Claude Code 가 수시로 다시 쓰므로 해석에 실패할 수 있다), 없거나 못 읽으면 null. 캐시의 `clear()` 는 계정을 바꾼 뒤 부른다 (그 전에 시작한 옛 계정 조회 결과는 캐시에 넣지 않는다)

JSON 해석 오류는 원문을 담지 않는 `UnreadableFileError` 로 바꾼다 (V8 의 JSON 오류 문구는 원문 일부를 담아 토큰이 로그·응답으로 샌다). 단위 테스트 `accounts.test.ts`

- `server/src/accountLogin.ts` — claude 실행: 웹 로그인 `makeLoginManager`(한 번에 하나, 10분 뒤 저절로 끝냄, 뜰 때 15분 넘게 남은 임시 폴더를 지운다(서버가 죽어 남은 것. 토큰이 들어 있을 수 있다), 서버가 끝나면 기다리던 claude 를 끈다)와 한 번 실행 `runClaudeAuth`(`claude auth logout`, 30초). claude 경로는 호스트와 같은 규칙(`--claude=` → `PRAY_CLAUDE` → PATH 의 `claude.exe`. 트레이는 서버에 `--claude=` 를 넘기지 않아 PATH 로 찾는다). 자식 env 는 `CLAUDECODE`·`CLAUDE_*` 를 지우고, 임시 폴더 실행이면 `CLAUDE_CONFIG_DIR`·`ANTHROPIC_CONFIG_DIR`(그 안 `anthropic`)·`BROWSER`(where.exe)를 넣는다. pty 없이 파이프다 (`auth login` 은 stdin 을 줄 단위로 읽고, 출력에 제어 문자가 없다). 단위 테스트 `accountLogin.test.ts`(node 로 띄운 가짜 claude)
- `web/src/UsagePanel.tsx` — 화면 아래 상태 표시줄 왼쪽의 사용량 한 줄 "Remaining 5h 62% · wk 80% · Fable 90% ↻"(한도별 툴팁은 리셋까지 남은 시간 "Resets in 2h 13m"). 서버가 주는 사용률을 **남은 비율**로 바꿔 보여 준다. 60초 폴링, 남은 30%↓ 노랑·10%↓ 빨강. **↻ 를 뺀 줄 전체가 버튼**이라 누르면(키보드 Enter 도) 바로 위에 상세 창이 뜨고 다시 누름·바깥 클릭·Esc 로 닫힌다 (Esc 는 포커스가 창 안이었으면 버튼으로 돌린다. 계정 추가·전환 모달이 떠 있으면 Esc 는 모달만 닫는다). 바깥 클릭은 `contains` 가 아니라 mousedown 의 `composedPath()` 로 본다 — 모달 오버레이를 누르면 React 가 window 리스너보다 먼저 모달을 지워 target 이 DOM 에서 빠지고, 그러면 상세 창까지 닫혔다. **상세 창은 Claude 앱 사용량 창의 배치를 밝은 테마 색(`:root` 변수)으로 따른 것이고 문구는 영어다**: 머리 = 주황 Claude 별(`ClaudeMark`, SVG 빛살 12개) + 굵은 "Claude", 그 아래 회색 "Updated just now·3m ago·2h ago"(fetchedAt), 옅은 구분선. 한도마다 굵은 이름("Session"·"Weekly"·모델별 한도는 모델 이름 "Fable", 모르는 kind 는 label) · 남은 비율 막대(기본 회색 `--muted`, 같은 색 규칙) · 그 아래 왼쪽 "62% left"(노랑·빨강이면 글도 같은 색), 오른쪽 "Resets in 56m·2h 13m·4d 12h"(resetsAt 이 날짜가 아니면 없음). 리셋 날짜·시각 "Resets Sat, Oct 24, 14:00"(이 PC 시각)은 그 줄의 툴팁. 구분선 아래는 계정 목록(`Accounts.tsx`)이고 사용량을 못 받아도 늘 보인다 (로그아웃 상태에서 계정을 넣어야 해서. 사용량 응답의 `email` 은 화면이 더 쓰지 않는다). 계정 추가·전환 모달은 상세 창 안이 아니라 그 형제로 `.usage` 안에 렌더한다 (전환 모달은 Accounts 가 넘겨받은 `.usage`(`modalRoot`)로 `createPortal`) — 상세 창(fixed, z-index 8) 안에 두면 모달이 그 쌓임 맥락에 갇히고, `.usage` 밖(포털)에 두면 모달 클릭이 상세 창의 바깥 클릭이 된다. 창은 화면 높이를 넘으면 안에서 스크롤한다(`max-height`). 사용량 오류면 머리 아래 그 이유만 (서버 문구. 서버에 닿지 못하면 "Can't reach the server"). **창 안에는 ↻ 가 없다** — 새로 고침은 상태 표시줄 ↻ 이고, 이 ↻ 는 줄 버튼 밖 형제라 창을 열지 않고 창이 열려 있으면 닫지도 않는다. 상태 표시줄이 `overflow: hidden` 이라 창은 `position: fixed`(왼쪽 아래, 목록 열과 같은 300px. 폰은 양옆 16px)다 — 조상에 transform 을 넣으면 창이 잘린다. 폰에서 상태 표시줄이 넘치면(승인 대기 표시·긴 오류 문구) 사용량 끝의 ↻ 가 잘려 손으로 새로 고칠 수 없다 (60초 폴링만)

## 핵심 개념

- **사용량 토큰은 갱신하지 않는다.** 액세스 토큰(약 8시간)은 Claude Code 가 실행 중일 때 스스로 갱신해 파일에 다시 쓴다. 서버는 호출마다 파일을 다시 읽고 401 이면 "Token expired" 로 표시한다. refresh token 으로 직접 갱신하면 Claude Code 쪽 토큰과 충돌할 수 있어 일부러 안 한다
- **Claude 계정 전환 (한 번에 한 계정, A 방식).** 기본 폴더(`~/.claude/.credentials.json` + `~/.claude.json` 의 `oauthAccount`)에는 늘 한 계정만 있고 다른 계정은 보관함에 토큰째 둔다. 전환 = 보관한 계정 키를 기본 폴더에 넣기. 도는 claude 는 `.credentials.json` mtime 이 바뀌면 다음 요청부터 새 파일 토큰을 쓴다(실측, Claude Code 2.1.310) — 그래서 전환하면 이 PC 의 모든 claude(웹·터미널·IDE)가 그 계정을 쓴다. 서버가 토큰을 갱신하거나 기본 폴더 밖에서 쓰지 않는다 (사용량 토큰과 같은 이유). **전환하면 프롬프트 캐시가 미스 난다** — Anthropic 프롬프트 캐시는 조직마다 따로라, 캐시가 아직 살아 있는(최근 1시간 안에 쓴) 세션은 다음 차례에 대화 문맥 전체를 새 계정으로 다시 캐시에 쓴다 (평소 한 차례의 수십 배 비용·한도). 그래서 화면은 전환 전에 `GET /api/accounts/switch-impact` 로 그 세션들과 문맥 크기를 보여 준다. 반영: 서버 재시작
- **로그인 정보는 두 파일에 따로 써진다.** `.credentials.json`(평문)의 계정 키 `claudeAiOauth{accessToken, refreshToken, expiresAt, refreshTokenExpiresAt(ms), scopes, subscriptionType, subscriptionTypeSource, rateLimitTier}`·`organizationUuid`·`trustedDeviceToken`·`trustedDeviceEnrolledAfterRefusalAtMs`·`enterpriseGateway`·`designOauth`·`cloudSessionsOauth`(= Claude Code 가 다시 로그인할 때 지우는 키)와 `~/.claude.json` 의 `oauthAccount{accountUuid, emailAddress, organizationUuid, organizationName, displayName, …}`. 계정과 무관한 키(`mcpOAuth`·`coworkRemoteDevice` 등)는 전환해도 남긴다. 로그인할 때 Claude Code 는 `~/.claude.json` 의 조직 캐시 키 17개(`ORG_CACHE_KEYS`)를 지우므로 전환도 지운다. 쓰는 꼴은 Claude Code 와 같다: `.credentials.json` 은 압축 JSON, `~/.claude.json` 은 2칸 들여쓰기, 둘 다 끝 줄바꿈 없음, 같은 폴더 임시 파일 + rename. 링크로 바꿔 끼우지 않는다 (Claude Code 가 "Refusing to write through symlink" 로 거절한다)
- **계정 전환 잠금.** 전환·지금 계정 다시 로그인은 Claude Code 의 토큰 갱신 잠금 안에서 한다: `~/.claude/.oauth_refresh.lock` → 옛 `~/.claude.lock` 순서(Claude Code 와 같은 순서라 교착이 없다), `proper-lockfile`(Claude Code 에 번들된 것과 같은 4.x: mkdir 잠금, 잠금 폴더 mtime 이 stale 보다 오래되면 넘겨받기, update 간격으로 mtime 갱신), realpath false·stale 60초·update 5초. 약 8초 재시도 뒤 409. 소유자 기록 `.oauth_refresh.lock.owner` 는 쓰지 않는다 — 기록이 없으면 Claude Code 는 먼저 가로채지 않고 stale 규칙만 쓴다. `onCompromised` 를 꼭 준다 (기본값은 타이머 안에서 던져 서버가 죽는다). `~/.claude.json` 은 Claude Code 의 쓰기 잠금 `~/.claude.json.lock`(stale 10초) 안에서 읽고 바로 쓴다 (Claude Code 도 이 잠금 안에서 다시 읽어 합쳐 쓰므로 바꾼 oauthAccount 를 되돌리지 않는다). 잠금 안 순서: 지금 파일의 계정 키를 지금 계정 보관본에 되써 저장(최신으로) → `.credentials.json` 계정 키 교체(그 사이 refresh token 이 바뀌었으면 409) → `~/.claude.json` 교체(실패하면 `.credentials.json` 을 되돌린다). 갱신 저장은 Claude Code 쪽이 CAS(디스크 refresh token 이 보낸 것과 같을 때만)라 잠금 밖에서 바꿔도 덮이지는 않지만 잠금 안에서 해야 되쓰기가 최신이다
- **계정 판정 (가장 위험한 곳).** `claudeAiOauth` 에는 계정 ID 가 없고 두 파일은 따로 써져 그 사이에 엇갈릴 수 있다. 잘못 붙이면 다른 계정의 보관본이 덮여 그 계정을 잃는다. 그래서 기본 폴더 토큰의 계정은 확실할 때만 정한다: refresh token 이 보관본과 정확히 같으면 그 계정(같은 로그인), 아니면 Claude Code 가 쓰는 OAuth 프로필 API `GET https://api.anthropic.com/api/oauth/profile`(`Authorization: Bearer <accessToken>`, 바이너리의 `${BASE_API_URL}/api/oauth/profile`)의 `account.uuid` — 실제 계정으로 `oauthAccount.accountUuid` 와 같음을 확인했다. 조회가 실패하면(네트워크·401) 모름으로 두고 60초 뒤 다시 묻는다 (그 사이 목록 요청은 기다리지 않는다). `~/.claude.json` 의 oauthAccount 로 토큰의 계정을 정하지 않는다 — 다만 oauthAccount 는 자기 accountUuid 를 담고 있어 그 계정 보관본의 oauthAccount 갱신에는 쓴다. 모를 때: 전환 500(되쓸 수 없어 아무것도 안 바꾼다), 보관 계정 지우기 409(쓰는 중인 로그인을 폐기할 수 있어서), 목록은 보관하지 않고 activeId null. **최신 유지**: refresh token 은 갱신 때마다 바뀌고(rotation) 이미 쓴 토큰을 되살리면 로그인이 폐기될 수 있어 보관본은 늘 기본 폴더 최신 토큰으로 맞춘다 (`.credentials.json` 이 바뀔 때마다·전환 직전 잠금 안에서). 처음 보는 계정(터미널 `/login`)은 새로 보관한다. 감시 사이(최대 5초)에 갱신과 터미널 `/login` 이 연달아 오면 갱신된 토큰을 못 보고 그 계정 보관본이 옛 토큰으로 남는다 (다시 로그인해야 한다)
- **웹 로그인.** 임시 설정 폴더에서 `claude auth login --claudeai` 를 띄운다: `CLAUDE_CONFIG_DIR=<빈 폴더>` 면 `.credentials.json`·`.claude.json` 이 그 폴더에 생기고 기본 폴더는 안 건드린다. 약 0.25초 안에 `Opening browser to sign in…` · `If the browser didn't open, visit: <수동 URL>` · `Paste code here if prompted >` 가 나온다. 브라우저는 `BROWSER` 프로그램을 셸 없이 URL 인자 하나로 실행해 연다(없으면 `rundll32 url,OpenURL`) — where.exe 를 줘서 이 PC 에 아무것도 안 뜬다. 수동 URL 의 redirect_uri 는 `https://platform.claude.com/oauth/code/callback` 이라 어느 PC 브라우저에서든 로그인하고 화면에 뜬 `code#state` 를 붙여 넣는다 (localhost 콜백 포트는 127.0.0.1 에만 열린다). PKCE 값이 그 프로세스 메모리에 있어 코드를 넣을 때까지 프로세스를 살려 둔다. **claude 는 붙여넣기의 꼴(`#` 앞뒤가 비지 않음)만 보고 state 는 보지 않은 채 바로 토큰 교환을 하고, 실패하면 `Login failed: …` + 종료 코드 1 로 끝난다**(실측) — 그래서 서버가 URL 의 state 와 먼저 맞춰 다른 로그인의 코드는 claude 에 넣지 않고(400 `isLoginEnded: false`, 로그인 유지), claude 가 거절한 뒤에는 로그인이 끝나 다시 시작해야 한다(400 `isLoginEnded: true`. 화면은 이것으로 다시 넣게 할지 새로 시작하게 할지 가른다). 성공하면 `Login successful.` + 종료 코드 0 → 임시 폴더의 계정 키와 oauthAccount 를 보관하고 폴더를 지운다. **임시 폴더에서 logout 하지 않는다**(그 로그인이 폐기된다). 새 계정은 보관만 하고 전환하지 않는다. 이미 보관한 계정은 보관본을 바꾸고, 그것이 지금 기본 폴더 계정이면 기본 폴더 로그인도 새 것으로 바꾼다 (그 계정은 기본 폴더가 기준이라 보관본만 바꾸면 다음 동기화가 옛 토큰으로 되돌린다)
- **로그아웃·폐기.** `claude auth logout` 은 refresh token(`claudeAiOauth`·`designOauth`·`cloudSessionsOauth`)을 서버에 폐기 요청(revoke)하고 `.credentials.json` 을 통째로 지운다(`coworkRemoteDevice` 만 남긴다 — `mcpOAuth` 도 지워진다). login 은 이전 계정을 폐기하지 않는다. 폐기 요청이 실패해도(네트워크) "continuing with local logout" 로 종료 코드 0 이라, 지우기·로그아웃이 성공해도 서버 쪽 폐기는 확인하지 못한다. **`claude auth logout` 은 `CLAUDE_CONFIG_DIR` 와 별개로 `ANTHROPIC_CONFIG_DIR`(없으면 `%APPDATA%\Anthropic`)의 프로필 자격 증명도 폐기·삭제한다** — 그래서 임시 폴더 실행에는 `ANTHROPIC_CONFIG_DIR` 도 임시 폴더 안으로 준다 (이 PC 에는 `%APPDATA%\Anthropic` 이 없다). 보관 계정 지우기 = 그 계정 키만 든 임시 폴더에서 `claude auth logout` 뒤 보관함에서 빼기. 지금 계정 로그아웃 = 기본 폴더에서 `claude auth logout`(이 PC 의 모든 claude 가 로그아웃된다) 뒤 보관함에서도 빼기

## 확인하지 못한 것

- Claude 계정 서버 쪽은 단위 테스트와 시험 서버(임시 홈의 가짜 토큰 파일, 가짜 프로필·사용량 API, CONNECT 를 막는 가짜 프록시)로만 확인했다: 자동 보관, 감시로 터미널 `/login`·토큰 갱신 따라가기, 전환(계정 키만 교체·mcpOAuth 유지·조직 캐시 삭제·사용량 캐시 비움), 잠금이 잡혀 있으면 409(새·옛 잠금 각각), 2분 묵은 잠금 넘겨받기, 보관 계정 지우기(실제 `claude auth logout` 을 임시 폴더에서. 폐기 요청은 프록시에서 막혔다), 실제 `claude auth login` 의 URL·꼴이 틀린 코드 400·다른 로그인의 코드 400(둘 다 로그인 유지)·claude 가 거절한 코드 400 뒤 끝남·취소·10분 만료. 못 본 것: 실제 로그인 성공(실제 claude 가 임시 폴더에 남기는 계정 키·oauthAccount 꼴. 성공 경로는 가짜 claude 로만), 실제 계정으로 전환한 뒤 도는 웹·터미널 claude 가 새 계정으로 바뀌는지, 실제 Claude Code 가 토큰을 갱신하는 동안 전환해 서로 잠금을 기다리는지(잠금 꼴·경로·stale 은 바이너리 문자열로 맞췄다), 실제 폐기 요청이 서버에 닿는지, 기본 폴더 로그아웃(가짜 실행기 단위 테스트와 `--claude=` 로 다른 실행 파일을 준 시험 서버만), 프로필 API 가 안 될 때(오프라인)의 실제 흐름, 화면(FE)과 붙인 흐름, 트레이가 띄운 서버가 PATH 로 claude 를 찾는지
