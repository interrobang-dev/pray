# Files 탭 (세션 작업 폴더 보기)

세션 패널의 세 번째 탭 Files — 고른 세션의 cwd 를 IDE 처럼 본다. 왼쪽 칸은 파일 트리(Files)·git/SVN 작업 트리 변경 목록(Changes)·cwd 전체 내용 찾기(Search, Ctrl+Shift+F)·git 커밋 히스토리(History) 넷이고(코드 보기 안 찾기는 Ctrl+F), 파일·diff 의 줄을 골라 그 위치(`경로:12-20`)를 이 세션 대화 입력칸에 넣거나 복사한다. **기존 글 파일 고치기는 이 PC(127.0.0.1) 접속에서만** 된다 (연필 버튼 → CodeMirror 편집기 → Save). 새 파일·지우기·이름 바꾸기와 형상관리 쓰기(stage·commit·revert·update·checkout·reset)·커밋 검색은 하지 않는다.

다른 파일에 있는 항목:
- 서버 API 꼴·경로 검증·숨김 목록·찾기 점수·인코딩 → server-api.md (`index.ts` 의 "세션 작업 폴더(cwd) API", `workspaceFiles.ts`). **변경 보기(`workspaceChanges.ts`)·커밋 히스토리(`workspaceHistory.ts`)·내용 찾기(`workspaceSearch.ts`) API 는 이 파일이다** (server-api.md 가 4만 자에 닿아서)
- 패널 탭 세그먼트·`shownTab` → web-app.md (`App.tsx`)
- scratchpad 작업 파일 모달(대화 오른쪽 아래 폴더 버튼, `Files.tsx`)은 다른 기능이다 → chat.md. `formatSize` 만 그 파일 것을 쓴다
- 저장 API·loopback·줄바꿈/BOM 되살리기·제자리 쓰기 → server-api.md (`workspaceSave.ts`), Origin·Host 판정 → security.md. 고르기 창 `choiceDialog`·App 의 탭·세션 바꾸기 → web-app.md
- 대화 입력 상자(`Composer.tsx`)·`CopyButton` → chat.md. 입력칸 글·커서 저장소 `composerDraft.ts` 는 이 파일이다 (아래 구조)

SVN 은 cwd 에서 `diff --internal-diff --force -- 경로` — **`--force` 는 svn 이 add 때 비ASCII 가 많은 글(한글·EUC-KR 소스)에 바이너리 mime-type 을 붙여 diff 를 막아서다** (실측: UTF-8 한글 두 글자 파일도 막혔다). 경로의 `@` 는 diff 에서 peg 로 읽히지 않는다(실측 — 끝에 `@` 를 붙이면 오히려 못 찾는다). `decodeDiffOutput`: 줄마다 UTF-8(fatal) → 안 되면 EUC-KR — SVN 은 `Index:`·`---` 머리의 경로가 코드 페이지(CP949)이고 내용은 파일 바이트라 한 출력 안에서 섞인다. 줄 끝 CR 은 뗀다. `parseUnifiedDiff`: hunk 머리의 옛·새 줄 수만큼만 읽어 끝을 안다(SVN 속성 변경 절의 `## -0,0 +1 ##`·`+값` 이 앞 hunk 에 붙지 않게), `\` 줄은 앞 줄의 `hasNoNewline`, hunk 밖 "Binary files"·"GIT binary patch"·"Cannot display: file marked as a binary type." 와 hunk 안 줄의 NUL 은 binary(`--force` 로 받은 진짜 바이너리), "Property changes on:" 은 `hasPropertyChanges`, `encoding` 은 hunk 안 줄 중 EUC-KR 로 푼 것이 있으면 euc-kr(머리 줄은 세지 않는다). 실측(시험 서버, 이 저장소 변경 14개): 목록 약 60ms, 임시 SVN 작업 사본 약 190ms, diff 한 파일 20~80ms

## 핵심 개념

- **모든 세션에 탭이 있다** (근무·휴식·퇴근·외부). 읽기만 해서 pty·claude 와 무관하다. 기준 폴더는 서버가 세션 목록과 같은 규칙으로 정한 cwd 다
- **세션별 기억**: 모듈 전역 Map(`sessionViews`)에 세션마다 받은 폴더 목록·펼친 폴더·고른 파일·파일별 고른 줄 범위(`lineRanges`)·왼쪽 칸 Files/Changes/Search(`sideMode`)·고른 변경 파일·변경 파일별 고른 diff 줄(`diffRanges`, row 번호)·마지막 변경 목록·Search 입력·토글·마지막 결과·접은 파일(`search`)·커밋 히스토리 거르기·목록·고른 커밋과 파일(`history`, 아래 "커밋 히스토리")을 둔다 (Search 를 다시 열 때 지금 입력의 결과가 없으면 다시 찾는다. 코드 보기 찾기 막대는 FilesTab state 라 탭을 떠나면 닫힌다) — 탭을 바꾸거나 다른 세션을 보고 와도 그대로이고(받은 목록을 먼저 보이고 열 때 다시 받는다), 페이지를 새로고침하면 사라진다. 폰에서 보기 칸을 띄웠는지(`isViewing`)는 기억하지 않아 다시 열면 트리부터다
- **줄은 React 요소가 아니라 innerHTML 한 번이다** — 몇 천 줄을 요소로 만들지 않으려고. 줄 번호는 `.code-line::before { content: attr(data-line) }`(sticky left, 패널 바탕)라 선택·복사에 끼지 않고 가로 스크롤해도 왼쪽에 붙어 있다. 번호 칸 폭은 줄 수 자릿수(`--gutter-digits` × 1ch). 측정(Vite dev·React 개발 빌드, headless 1400×900, 고르기 → 줄이 그려지고 두 번째 rAF, 받기 포함): App.tsx 1,962줄 약 220ms, style.css 5,104줄 약 250ms, package-lock.json 5,949줄 약 355ms. Node 에서 강조만: 84KB 54ms, 252KB 93ms, 420KB(9,810줄) 124ms. 1MB 가까운 파일의 화면 그리기는 재지 않았다
- **줄 고르기** (`useLineSelection` — CodeView·DiffView): 줄 번호 칸 클릭 = 그 줄, 이미 그 한 줄만 골라 있으면 풀기, Shift+클릭 = 시작 줄(마지막 그냥 클릭·드래그를 시작한 줄, 다시 연 파일이면 범위 시작)부터. 코드 보기의 번호 칸은 sticky `::before` 라 요소가 없어, 클릭 x 가 보기 왼쪽에서 `::before` 의 폭·안쪽 여백·오른쪽 선·바깥 여백 합 안인지로 가린다 (diff 는 번호 칸이 요소 `.diff-gutter` 라 그 안인지로). 번호 칸 mousedown 은 기본 동작을 막고 글자 선택을 지운다 (Shift+클릭이 글자 선택을 늘리지 않게). **글자 드래그는 document `selectionchange` 로 본다** — 선택 양끝이 이 보기의 줄(`.code-line`·`.diff-row`) 안이면 걸친 줄을 고르고(끝이 다음 줄 맨 앞이면 그 줄은 뺀다), 접힌 선택(그냥 클릭)은 무시해 고른 줄이 남는다. mouseup 이 아니라 selectionchange 인 것은 폰의 길게 눌러 고르기도 잡으려고다 (끌어가는 동안 범위가 따라 바뀐다). 두 방법은 같은 범위 하나를 바꾸고 마지막에 한 것이 이긴다. 고른 줄 표시는 줄 요소의 class `is-selected`(바탕·번호 칸 `--accent-soft`, 번호 `--accent-text`. diff 는 옅은 초록인 추가 줄과 구분되게 번호 칸 왼쪽 3px `--accent` 막대·굵은 번호를 더한다)를 layout effect 로 직접 붙이고 뗀다 (줄이 innerHTML 이라). 폰은 번호 칸 탭 = 한 줄(Shift 가 없다)이고 범위는 글자 길게 눌러 고르기. 다시 읽은 파일이 줄었으면 범위를 자르고, 시작 줄까지 없어졌거나 글 파일이 아니게 됐으면 뺀다 (diff 도 다시 받은 diff 의 줄 수로 같게). 단축키는 없다
- **diff 에서 공유하는 위치는 새 파일 줄 번호다** (`diffLineRange`): 고른 줄 중 새 번호가 있는 줄(문맥·추가)의 처음~끝. **지운 줄만 골랐으면 지운 자리 바로 뒤의 새 줄**(파일 끝이면 바로 앞 줄) 한 줄 — 새 파일에는 그 줄이 없어 옛 번호를 주면 claude 가 지금 파일에서 엉뚱한 줄을 본다. 새 줄이 하나도 없으면(지운 파일) 경로만. hunk 머리만 고르면 경로만
- **Changes 목록은 탭을 열 때 받는다** (Files 쪽을 보고 있어도 — 전환 버튼 개수 배지 때문. 서버는 같은 폴더를 돌리는 중이면 같이 기다린다) · ↻ · 머리줄 ↻ 때. 저절로 다시 받지 않는다 (claude 가 파일을 고쳐도 ↻ 전까지 그대로). diff 는 Changes 쪽에서 파일을 고를 때·↻ 때 받는다. **Open in Files** 는 Files 쪽으로 바꾸고 빠른 찾기처럼 조상 폴더를 펼쳐 그 파일을 연다 (고른 diff 줄은 옮기지 않는다). 빠른 찾기로 연 파일도 Files 쪽으로 바꾼다
- **Add to chat**: App 의 `addToChat` 이 `addToComposerDraft`(위 `composerDraft.ts`)로 대화 입력칸 글의 마지막 커서 자리(선택이 있었으면 그 글을 바꾼다. 모르면 끝)에 `` `경로:12-20` `` 을 넣고(앞 글자가 공백이 아니면 앞에 한 칸, 뒤가 비었거나 공백이 아니면 뒤에 한 칸) 대화 탭으로 바꾼다. Files 탭이 열린 동안 Chat·Composer 는 언마운트돼 있어 ref 로 부를 수 없다 — 그래서 모듈 저장소에 넣고, 입력칸이 마운트될 때 그 글·커서로 그리고 포커스한다 (터치 기기도 — 사람이 누른 버튼이다). App·Chat 의 렌더 구조와 Composer 의 글 state 는 그대로다. 막는 때는 근무 중인 웹 세션이 아닐 때다 (`addToChatBlockReason`: 외부 "started from a terminal or IDE, so this session is view-only"·퇴근 "this session is off duty"·휴식 "this session is on a break"). 질문 중에는 막지 않는다 (입력칸이 잠겨도 글은 들어가 남는다). 경로는 세션 cwd 기준 `/` 구분(트리 경로 그대로)
- **받은 파일에는 경로가 붙어 있다**(`FileState.path`). 지금 고른 것과 다르면 받는 중으로 본다 — 고른 직후 한 번 그릴 때 앞 파일 내용이 새 경로 아래 보이던 것을 막는다. ↻ 로 같은 파일을 다시 받는 동안은 앞 내용을 둔다
- **편집** (`FilesTab`): 글 파일을 보는 중 연필을 누르면 그 자리가 편집기가 되고(`editingPath`), 다시 누르거나 다른 파일을 열면 보기로 돌아온다. **할 수 있는지는 서버가 파일 응답의 `editBlockReason` 으로 정한다** — 다른 PC("Editing works only on this PC (open it at 127.0.0.1)")·`.git`·`.svn`·`.hg` 안·EUC-KR("saving would change the encoding") 이면 연필이 막히고 title 에 이유. 필드가 없으면(재시작 전 옛 서버) "The server needs a restart to support editing". 보기 모드(줄 고르기·Add to chat)는 그대로이고 편집 중 Add to chat·Copy path 는 **누를 때 편집기에서 고른 줄**(고른 것이 없으면 경로만)을 쓴다 (편집기 커서마다 FilesTab 을 다시 그리지 않으려고. 경로 표시줄 ":12-20" 은 편집 중 안 보인다). **저장**: Save·Ctrl+S → `PUT file` 에 편집기 글과 열 때(또는 마지막 저장)의 `hash`. 성공하면 파일 정보(hash·mtime·크기)와 보기 글을 바꾸고 ● 를 끄고 변경 목록을 다시 받는다(개수 배지). 바뀐 것이 없으면 보내지 않는다. **409**(디스크 파일이 바뀜): `choiceDialog` "File changed on disk" — Cancel(처음 포커스) · Reload(편집을 버리고 다시 받아 편집기 글을 바꾼다) · Overwrite(빨강, 서버가 준 지금 hash 로 다시 보낸다). 그 밖 실패는 `alertDialog` "Save failed"(서버 문구). **Ctrl+S**(맥 Cmd+S): 편집기 안은 편집기 키맵이, 편집기 밖은 편집 중이고 포커스가 Files 탭 안(또는 아무 데도 없음)이고 모달이 없을 때 window keydown 이 `preventDefault` 한다 (브라우저 저장 창을 막는다. 바뀐 것이 없으면 막기만 한다). **저장 안 한 편집이 사라지기 전 확인 창**("Unsaved changes" · "<경로> has unsaved changes. Discard them?" · Cancel(포커스)/Discard): Files 탭 안 — 다른 파일(트리·빠른 찾기)·Changes 전환·↻·연필(그만두기), App — 대화·터미널 탭·다른 세션 고르기(목록·사무실·상태 표시줄 승인 대기·Shells)·패널 닫기·플로우 열기·Add to chat. 편집기 글은 FilesTab 안에만 있어 탭이 언마운트되면 사라지기 때문이다 (탭을 다녀와도 편집 모드는 이어지지 않는다). 창 닫기·새로고침은 `beforeunload` 의 브라우저 기본 창 (앱 안 창을 띄울 수 없다). 편집기는 한 번에 하나라 기록도 경로 하나다
- **Ctrl+P·Ctrl+F·Ctrl+Shift+F(맥 Meta)는 Files 탭이 열려 있고 `.modal-overlay` 가 없을 때만** FilesTab 의 window keydown 하나가 받는다 (컴포넌트가 마운트된 동안만 리스너가 있어 다른 탭·세션 미선택·모달에서는 브라우저 그대로. 대화 탭 Ctrl+F 는 App 의 대화 검색 그대로). 한글 자판에서도 되게 `code` 로도 본다. 이미 `defaultPrevented` 면(편집기 키맵이 받았으면) 건드리지 않는다. **Ctrl+P** = `preventDefault` + 빠른 찾기 포커스(글 전체 선택) — 브라우저 인쇄를 가로챈다. **Ctrl+F** = 글 파일을 보고 있을 때만(Files·Search 쪽, 폰이면 보기 칸을 띄운다) 가로채, 보기 모드는 찾기 막대를 열고(열려 있으면 입력칸 포커스·전체 선택) 편집 중이면 편집기 찾기 패널을 연다 (편집기 안이면 CodeMirror 키맵이 먼저 열고 막는다, 편집기 밖이면 `openSearch`). 글 파일이 없을 때(트리만·그림·바이너리·Changes 의 diff)는 막지 않아 브라우저 찾기다 — diff 에는 자체 찾기가 없어서. **Ctrl+Shift+F** = 늘 가로채 Search 로 바꾸고(폰은 목록 칸) 입력칸 포커스·전체 선택. 보기 칸(`.ws-view` — 코드·diff)의 글자 선택이나 편집기 선택이 있으면 `selectionQuery` 로 그 글을 검색어로 넣고 바로 찾는다. CDP 키 입력으로 keydown 의 `defaultPrevented` 까지만 확인했다 (실제 OS 키로 인쇄·찾기 창이 안 뜨는지는 보지 않았다)
- **찾기 (Ctrl+F, `CodeFindBar`)**: 입력은 바로 보이고 찾기는 120ms 모아서(입력 직후 Enter 는 지금 글로 바로 찾기만), Enter 다음·Shift+Enter 이전(끝에서 돈다, 한글 조합 중 Enter 무시), Esc 는 막대만 닫는다(이벤트를 멈춰 패널이 안 닫힌다. 닫으면 칠한 것을 지운다). 대상은 코드 보기의 줄 글(`normalizeText` 를 `\n` 으로 나눈 것 — 줄 번호가 화면과 같다), 대소문자 무시가 기본(Aa 로 켠다). 새 검색어는 **지금 보이는 맨 윗줄이나 그 뒤의 첫 맞은 곳**에서 시작해(뒤에 없으면 처음) 그곳으로 스크롤하고, ↻ 로 글만 바뀌면 번호를 맞춰 두고 스크롤하지 않는다. 시작 번호는 layout effect 로 정한다 (아니면 한 프레임 "0/17" 이 보였다). **칠하기는 보이는 줄 ±150줄만** CSS Custom Highlight API 로 하고 스크롤하면 한 프레임에 한 번 다시 칠한다 — 맞은 곳이 수만 개여도 Range 를 다 만들지 않게 (줄은 innerHTML 이라 DOM 을 건드리지 않는다). 현재 맞은 곳은 진한 색이고 그 줄이 보기 위아래 끝이나 밖이면 가운데로, 가로는 번호 칸에 가리거나 오른쪽 밖일 때만 옮긴다. 입력 글·결과·번호는 막대 state 라 칠 때 코드 보기는 다시 그리지 않는다. 검색어·Aa 는 FilesTab 이 기억해 다른 파일을 열어도 막대가 열린 채 같은 글로 찾는다. 줄 고르기·Add to chat 과 따로 돈다 (막대 입력칸의 선택은 줄 밖이라 `selectionchange` 가 무시한다). 측정(Vite dev·headless, package-lock.json 6,581줄): 글자 하나 CDP 왕복 약 25ms, 마지막 글자 뒤 개수가 나오기까지 약 160ms(디바운스 120ms 포함)
- **작업 폴더 내용 찾기 (Ctrl+Shift+F)** — 서버 `GET /api/sessions/:id/search?q=&case=&word=&regex=`(기준 폴더·인증은 Files 탭 API 와 같은 `workspaceRootOf` — 읽기만이라 로그인한 다른 PC 도 된다. `Cache-Control: no-store`) → `{ files: [{ path, matchCount, matches: [{ line, column, text, ranges: [[시작, 끝]], hasMoreAfter }] }], matchCount, fileCount(맞은 파일 수), searchedFileCount(실제로 찾아 본 수), isTruncated, isIndexPartial, elapsedMs }`. 거절: 세션 ID 꼴 400 "Invalid session ID" · q 가 1~500자 글이 아님 400 "Query must be 1 to 500 characters"(공백만인 글도 찾는다) · case·word·regex 가 없음·0·1·true·false 가 아님 400 · 정규식 문법 오류 400(V8 영어 문구) · 기준 폴더 없음 404 "Session folder not found" · 같은 세션의 새 검색이 와서 끊김 409 "A newer search replaced this one" · 동시에 4세션(`MAX_RUNNING_SEARCHES`)이 찾는 중 503.
  - **범위**: 빠른 찾기와 같은 파일 목록(`buildFileIndex`·30초 캐시 — 숨김 폴더·링크 제외, 5만 개·3초)에서 1MB 넘는 파일·NUL 이 든 파일은 건너뛰고, 글은 `decodeText`(UTF-8 → EUC-KR)
  - **규칙**: 줄 단위(`\n` 으로 나누고 CR 은 지운다 — 코드 보기 줄 번호·글과 같다). 정규식은 `u` 플래그(대소문자 무시면 + `i`)라 문법이 엄격하다. 글자 그대로 찾기는 정규식 문자를 이스케이프한 것. **낱말 단위는 앞뒤가 `\p{L}\p{N}_` 가 아닐 때** (`\b` 는 ASCII 만 알아 한글 낱말 경계를 못 본다 — "세션을" 안의 "세션" 은 낱말이 아니다). 빈 일치(`^`·`a*`)는 세지 않는다
  - **상한**: 맞은 곳 2,000개(`MAX_MATCHES`)·요청 전체 5초(`SEARCH_TIME_LIMIT_MS` — 파일 목록 받기에 쓴 시간을 뺀 나머지를 worker 에 준다, 최소 500ms)에서 멈추고 `isTruncated`. 결과 줄 글은 300자(`MAX_PREVIEW_CHARS`): 넘는 줄은 첫 맞은 곳 앞 40자부터 자르고 ranges 를 그 안으로 옮기며(밖은 빼고 걸친 것은 자른다, 서로게이트 쌍은 안 나눈다) `column`·`hasMoreAfter` 로 알린다. `matchCount` 는 자른 줄 밖의 것도 센다. 파일은 경로순(숫자는 값으로)
  - **worker 스레드에서 찾는다** (`runSearchWorker`) — 사용자 정규식의 파국적 되돌아가기(`(a+)+$`)가 서버 이벤트 루프를 멈추지 않게. worker 는 파일 사이·256줄마다 시간을 보고 스스로 멈추고, 정규식 한 번이 끝나지 않으면 300ms 더 기다린 뒤 서버가 `terminate()` 한다 (그때까지 받은 파일 결과는 남긴다). 같은 세션의 새 검색·요청 끊김(`res` 의 close. `req` 의 close 는 GET 본문을 다 읽자마자 와서 쓰지 않는다)도 `terminate()`. **worker 파일은 `.ts` 그대로** `new URL('./workspaceSearchWorker.ts', import.meta.url)` 로 띄운다 — 서버는 트레이(`node --import tsx`)·`npm run dev`(`tsx watch`)·`start`(`tsx`) 모두 tsx 로 돌고 Worker 는 부모 execArgv(tsx 로더)를 물려받는다 (`node --import tsx`·`tsx` 로 확인, `tsx watch` 는 같은 로더라 보지 않았다). 그래서 vitest 안에서는 worker 를 띄우지 못해 테스트는 순수 함수만이다. worker 는 검색마다 새로 띄워 worker 코드를 고치면 서버 재시작 없이 다음 검색부터 새 코드다
  - 측정(시험 서버): 이 저장소(약 300 파일) 첫 검색 약 1.3초(파일 목록 + worker 의 tsx 변환), 그 뒤 약 180ms(대부분 worker 띄우기). `D:/workspace` 를 cwd 로 하면 파일 목록이 3초 상한에 걸리고 남은 2초에 수십~수백 파일만 찾아 안내 두 줄이 뜬다. `(a+)+$` 를 `a`×36 + `!` 줄에 걸면 5.3초에 끝나고 그동안 `GET /api/sessions` 는 약 1.5ms, 요청을 끊으면 서버 CPU 가 바로 0
  - **화면**(`SearchPanel`): 입력은 300ms 모아서, Enter(같은 검색이면 다시 찾기 — 파일이 바뀌었을 때)·토글은 바로 찾고 앞 요청은 AbortController 로 끊는다. 이미 그 검색의 결과·오류가 있거나 도는 중이면 다시 보내지 않는다. Esc 는 입력칸 포커스만 뺀다(이벤트를 멈춘다). **결과 줄을 누르면** 그 파일을 열고(다른 파일이면 저장 안 한 편집 확인 뒤) 그 줄을 골라 두고(`lineRanges` — 경로 표시줄 ":574", 바로 Add to chat·Copy path) 코드 보기를 그 줄로 스크롤한다. 편집 중인 그 파일이면 편집기에서 그 줄을 고르고 가운데로 스크롤한다 (`revealLine`). 트리는 펼치지 않는다. 폰은 보기 칸을 띄우고 ← "Back to search" 로 결과(그대로 남는다)에 돌아온다
- **변경 보기 API**(규칙은 위 `workspaceChanges.ts`, 기준 폴더는 Files 탭 API 와 같은 `workspaceRootOf`): `GET /api/sessions/:id/changes` → `{ kind: 'none' }`(형상관리 없음) 또는 `{ kind: git·svn, branch, files: [{ path, status, oldPath }], isTruncated, hiddenCount, error }` — git·svn 이 없거나 명령이 실패·시간 초과해도 200 + `error`(영어 문구, files 는 빔). 세션 ID 꼴이 틀리면 400, 기준 폴더가 없으면 404. `GET /api/sessions/:id/changes/diff?path=`(cwd 상대, 꼴 검사는 `isValidRequestPath`) → `{ kind: diff·binary·too-large·empty, path, status, oldPath, hunks: [{ header, oldStart, oldLines, newStart, newLines, lines: [{ kind: context·add·del, text, oldLine, newLine, hasNoNewline? }] }], encoding, hasPropertyChanges }` — 변경 목록에 없는 경로는 404 "Not a changed file"(그래서 임의 경로·숨김 폴더 안 파일의 diff 는 못 받는다), diff 명령 실패는 502 + 영어 문구. 둘 다 `Cache-Control: no-store`.
- **커밋 히스토리 (History, git 만)** — 서버 `GET /api/sessions/:id/history?skip=&path=` → `{ kind: git·svn·none, commits: [{ hash, shortHash, subject, authorName, authorDate(ISO), refs, isHead }], hasMore, error }`(50개씩, skip 은 0~7자리 숫자, path 는 `isValidRequestPath` + `..`·`.`·빈 칸 없는 cwd 상대 — 지운 파일 기록도 보게 파일이 있는지는 안 본다. 꼴이 틀리면 400, 기준 폴더 없음 404, SVN·형상관리 없음은 kind 만, git 실패는 200 + `error`) · `GET …/history/:rev`(4~64자 hex, 아니면 400) → `{ hash, shortHash, subject, body, authorName, authorEmail, authorDate, parents, files: [{ path, status, oldPath }], outsideCount, isTruncated }`(없는 커밋·git 아님 404 "Commit not found", git 실패 502) · `GET …/history/:rev/diff?path=` → Changes diff 와 같은 꼴(그 커밋 파일 목록에 없으면 404 "Not a file in this commit"). 셋 다 `Cache-Control: no-store`, 기준 폴더·인증은 Files 탭 API 와 같고 읽기만이라 로그인한 다른 PC 도 된다. 작성자 메일은 저장소에 이미 있는 값이라 상세에 싣고 화면은 이름의 툴팁으로만 보인다.
  - **범위**: 목록은 HEAD 에서 거슬러 cwd 아래를 건드린 커밋만(`-- .`) — 경로를 거른 log 라 **git 기본 히스토리 단순화**를 따른다: 그 폴더 기준으로 한쪽 부모와 같은 머지 커밋은 안 보인다(저장소 루트에서는 보이던 머지가 하위 폴더 cwd 에서는 빠진다. 시험으로 확인). 파일 내용이 바뀌지 않은 커밋(빈 커밋)도 안 보여 이 저장소는 `git log` 235개 중 234개. 상세·diff 는 **첫 부모 대비**(머지면 "Merge commit · changes against the first parent abc1234", 첫 커밋은 빈 트리 대비 "Initial commit"), cwd 밖 파일은 빼고 "N files outside this folder not shown". 파일별은 `--follow` 라 이름 바뀌기 전 커밋까지 보이지만, 그 옛 커밋의 상세에서는 옛 이름으로 보인다
  - **화면 왼쪽**(`HistoryPanel`): 머리줄은 Changes 와 같은 `.ws-changes-head` — 왼쪽 "git · main"(브랜치는 Changes 목록이 받은 것) 또는 파일별이면 강조색 칩 `.ws-history-filter`(파일 이름, 툴팁 "Commits that changed <경로>", × title "Show all commits"), 오른쪽 ↻ "Refresh history". 커밋 줄 `.ws-commit`: 제목(없으면 회색 기울임 "(no message)") / 고정폭 짧은 해시 · `formatAgo` · 작성자(회색 11px) / 브랜치·태그가 있으면 셋째 줄 칩 `.ws-ref`(지금 브랜치 `--accent-soft`·`--accent-text`, 태그 `--link` 테두리. 160px 칸에서 칩이 제목을 밀어내지 않게 따로 줄), 툴팁 "해시 제목 / 작성자 · formatDateTime / refs". 끝에 "Loading…"·"Couldn't load history: …"(빨강)·`historyNote`("Commit history is available for git only"·"Not a git repository"·서버 error 빨강·"No commits for this file"·"No commits yet")·`Load more`(받는 중 "Loading…"). 커밋을 누르면 같은 칸이 상세 `.ws-commit-pane` 이 된다: 막대(← "Back to commits" · 짧은 해시(툴팁 전체) · Copy hash(`CopyButton` label "Copy hash", **전체 해시**) · Add to chat `.ws-commit-add`) + 함께 스크롤하는 메시지(제목 굵게 · 본문 `pre-wrap` · 작성자(툴팁 메일) · 시각 · 부모 안내)와 바뀐 파일 줄(Changes 와 같은 `.ws-change`·상태 글자, 지운 파일은 취소선). 상세가 오기 전에는 목록에서 받은 제목·작성자를 먼저 보인다. 목록은 상세를 보는 동안 `hidden` 으로 숨겨만 둬 ← 로 돌아오면 스크롤 자리가 남는다
  - **화면 오른쪽**(`CommitDiffView`): 고른 커밋 없음 "Select a commit to see its changes", 파일 없음 "Select a file to see its diff", "Loading…", 실패 "Couldn't load the diff: …", 받으면 `DiffView`(Open in Files 없음, 줄 고르기 끔). **줄 고르기·Open in Files·위 막대의 Add to chat·Copy path 를 끈 이유: 지난 커밋 diff 의 줄 번호는 지금 파일과 달라** `경로:12` 로 공유하면 claude 가 지금 파일에서 엉뚱한 줄을 본다. 그래서 History 쪽 위 막대는 경로 표시줄(고른 커밋의 파일, 툴팁 "<전체 경로> at abc1234")·↻ 만 있고, 공유는 커밋 단위(해시)로만 한다

  - **세션별 기억**(`sessionViews` 의 `history`): 거르기·받은 목록(그 거르기와 함께)·고른 커밋·고른 파일. **받은 목록은 다시 열어도 다시 받지 않는다** — Load more 로 늘린 쪽이 남게. 새 커밋은 머리줄 ↻·위 막대 ↻ 로 첫 쪽부터 다시 받는다(목록이 50개로 줄어든다). 커밋 상세는 바뀌지 않아 모듈 Map(`세션|해시`, 100개)에 두고 다시 받지 않는다. diff 는 파일을 고를 때·위 막대 ↻ 때 받는다. 요청은 새 요청이 오면 끊고, 그 밖의 이유로 끊기면 "Loading…" 에 멈추지 않게 "Request was cancelled" 오류 줄로 보인다
  - 측정(시험 서버, 이 저장소): 첫 쪽 목록 약 170ms(curl), 상세 약 90~150ms(show + diff-tree + rev-parse 3번), 시험 저장소 목록 약 65ms
