# 서버 API·세션 목록·훅

Express 서버의 API 경로 전부, 세션 목록 합치기, jsonl 요약, 훅 상태, 백그라운드 shell, 작업 파일·첨부, 세션 cwd 파일 읽기·저장(변경 보기·커밋 히스토리는 workspace.md), AskUserQuestion, 세션 이름·역할·인물 저장, 폴더 신뢰 기록, 모델·effort 바꾸기를 다룬다.

원래 루트 `CLAUDE.md` 한 파일이던 내용을 옮긴 것이다. 본문의 "위·아래 …"·"핵심 개념 …" 은 그때의 말이라 가리키는 항목이 다른 파일에 있을 수 있다. 어디서나 지킬 규칙·근무·휴식·퇴근·표시 상태·실행 방법은 루트 `CLAUDE.md`, 다른 영역은 루트의 문서 지도를 본다. 이 영역을 고치면 이 파일의 그 줄을 고쳐 쓴다.

다른 파일에 있는 항목:
- 핵심 개념 "Claude 계정 전환" → accounts.md
- 핵심 개념 "worktree 파트" → team.md
- 핵심 개념 "표시 상태" → 루트 CLAUDE.md
- `recentMemberNames` → team.md
- 대기 메시지 취소·입력칸 알림(`/api/hook/prompt-box`)·작업 중지 규칙 → queue-interrupt.md
- 곁가지 질문의 흐름·실측·`btw.ts` → queue-interrupt.md (API 꼴은 아래 `index.ts`)
- 팀·파트·팀원 이름·모델 규칙 → team.md
- 계정 API 규칙 → accounts.md
- 대화 메시지(`messages.ts`) → chat.md (그 응답 캐시·증분 `messageCache.ts` 는 여기)
- 화면 쪽 증분 받기(`chatDelta.ts`) → chat.md
- 팀 할 일 저장 규칙·시작 때 옮기기 → host.md
- 인증(`auth.ts`)·Host 검사·Origin(CSRF) 검사·훅 경로 loopback 전용·미들웨어 순서·`isLocalPageRequest` 규칙 → security.md

## 핵심 개념

- **세션 이름은 사용자 지정(`hq.json.sessionNames`) → jsonl 의 `ai-title`(Claude Code 가 첫 대화 뒤 자동으로 붙이는 요약 제목) → ID 앞 8자리 순.** 패널 헤더의 ✎ 로 모달에서 바꾸고 비우면 자동 제목으로 돌아간다 (`PATCH /api/sessions/:id {name, position}`). 외부 세션에도 붙일 수 있다. 세션 추가 모달의 Name 칸(팀·파트 모달은 서버가 고른 이름이 미리 채워진다. 아래 모달 항목)과 팀원 이름(`team_spawn_member` 의 role 로 서버가 고른 이름. role 이 없는 옛 요청은 팀장이 준 name)도 여기에 저장한다. **역할(FE·Lead 등)은 이름에 넣지 않고 `hq.json.positions`(세션 ID → 역할, `Session.position`)에 따로 둔다** — 화면이 이름 앞에 붙여 보인다. 팀원 spawn 의 role, `POST`·`PATCH` 의 `position` 이 여기에 들어간다. 예전에는 이름이 `[FE] Jisoo` 꼴이었다: 서버가 시작할 때 `sessionNames` 의 그 꼴(괄호 안이 역할 꼴일 때만. `[Lead]`·`[Dev]`·`[Asst]` 도)을 역할과 이름으로 한 번 나누고(이름 부분이 비면 이름은 지운다, 이미 역할이 있으면 그 역할을 두고 이름에서만 뗀다), 그 뒤에도 API 로 옛 꼴 이름이 오면(옛 화면·옛 팀장) 나눠 저장한다 — 이름에 남으면 화면에 역할이 두 번 보인다. 웹 세션 이름은 퇴근 중에도 남아 퇴근 목록에서 "팀명 · 이름" 으로 보이고, 호스트가 퇴근 기록을 지울 때(forget·보관 기간)와 대화 없이 끝난 세션의 기록을 지울 때 같이 지워진다. 외부 세션 것은 계속 남는다. **도트 인물도 같은 방식**이다: `hq.json.characters`(세션 ID → `{ id, hair, top, isAuto? }`. `isAuto` = 새 세션(`POST /api/sessions`·팀원 spawn)에 서버가 배정한 것, 규칙 → office-art.md), `PUT /api/sessions/:id/character` `{ id, hair?, top?, isAuto? }`(`{ id: null }` = "Auto": 새로 배정, `isAuto: true` = 화면 Auto 버튼이 정한 인물을 자동 배정으로 저장(boolean 이 아니면 400), 꼴은 `server/src/character.ts` 의 `parseCharacter`: id 소문자·숫자·하이픈 1~40자, 색 `#rrggbb` 를 소문자로. 틀리면 400. 고른 인물 id 는 아틀라스와 대조하지 않아 없는 id 도 저장되고 화면이 무시한다). 고르기는 화면에서 지시자에게만 열고, 팀장을 해제해도 고른 인물은 남는다. 이름과 같이 지워진다. **성별** `hq.json.genders`(세션 ID → `male`·`female`, `Session.gender`)는 서버가 이름을 지을 때만 남는다: 팀원 spawn 의 role, `POST /api/sessions` 의 `gender`(화면은 추천 이름을 고치지 않고 쓸 때만 넘긴다. 이름이 없으면 무시). 직접 지은 이름·기존 세션은 없다. `PATCH` 로 이름이 그대로면(대소문자·앞뒤 공백 무시) 남기고, 바뀌거나 비우면 지운다 (새 이름과 성별이 안 맞을 수 있어서). 역할만 바꾸면 남긴다. 이름·인물과 같이 지워진다. 역할도 이름과 같이 지워진다. 고른 인물이 있으면 성별은 쓰지 않는다. Claude Code 의 `/rename`·`--name` 은 jsonl 에 안 남아 화면에 영향 없다
- **AskUserQuestion 은 훅으로 붙잡아 웹에서 답한다 (웹 세션만).** 질문 화면이 뜰 때 PermissionRequest 훅이 같이 돈다 (payload 에 `tool_name`·`tool_input` 은 있고 `tool_use_id` 는 없다). 서버는 질문 훅(`/api/hook/ask`, matcher `AskUserQuestion`) 요청에 응답하지 않고 세션당 하나 붙잡아 `Session.question` 으로 보이고, 같은 세션에 새 질문이 오면 옛것은 `{}` 로 놓아준다. `POST /api/sessions/:id/answer` 가 그 요청에 응답한다: `{ answers: { 질문문: string[] } }` → allow + `updatedInput`(원래 입력 그대로 + `answers`), `{ cancel: true }` → deny (Claude Code 의 도구 거부처럼 "STOP … wait" 문구라 claude 가 멈춘다), `{ chat: true }` → deny (Claude Code "Chat about this" 문구라 claude 가 무엇을 확인하고 싶은지 묻는다). 붙잡은 질문이 없으면 409, 답이 틀리면 400 (빠진 질문·빈 배열·빈 글·단일 선택에 2개 이상·모르는 질문). 터미널 화면과 경쟁해 먼저 결정한 쪽이 이긴다: 웹에서 답하면 터미널 질문 화면이 닫히고 "Allowed/Denied by PermissionRequest hook" 으로 남는다. 터미널에서 먼저 답하면 Claude Code 는 붙잡힌 요청을 끊지 않으므로 서버가 PostToolUse(AskUserQuestion)·Stop·SessionEnd·호스트 exit 때 `{}` 로 놓아준다 (연결이 먼저 닫히면 지우기만). 외부 세션·다른 도구·꼴이 다른 질문은 바로 `{}`. Claude Code 는 http 훅을 axios 로 보내고 훅 timeout 만 걸어서 6분 넘게 붙잡아도 연결이 그대로다. deny 에는 PostToolUse 가 오지 않으므로 서버가 응답 직후 그 세션 상태를 working 으로 돌린다 (`applyQuestionDenied`: pendingTool 비움, workingSince 유지. 다음 훅이 오면 평소대로). allow 는 PostToolUse 가 올 때까지(1초 안쪽) needs-approval(질문 없음)로 남는다. 질문은 서버 메모리에만 있다. PreToolUse 로 붙잡으면 터미널 화면이 아예 안 떠서 쓰지 않는다. 같은 PermissionRequest 에 걸린 orca 명령 훅(matcher `*`)은 질문에 결정을 내지 않는다
- 새 폴더에서 claude를 띄우면 신뢰 확인 대화상자가 뜨고 **기본 선택이 "No, exit"**다 (아무도 안 누르면 세션이 꺼진다). 그래서 **서버가 웹에서 새로 띄우는 세션(`POST /api/sessions`·팀원 spawn. resume 은 아님)의 폴더를 띄우기 전에 `~/.claude.json` 의 `projects["<키>"].hasTrustDialogAccepted = true` 로 기록한다.** 키는 Claude Code 가 쓰는 꼴(실제 경로, 드라이브 대문자, 디스크의 대소문자, 구분자 `/`. 예 `D:/workspace/@private/jk-corp`)이라 `d:\workspace\…` 로 와도 같은 키가 된다. 이 파일은 Claude Code 가 수시로 다시 쓰므로 이미 true 면 쓰지 않고, 쓸 때는 읽은 직후 그 키만 바꿔 바로 쓴다. 해석에 실패하면 쓰지 않고 세션은 그대로 띄우며 화면이 경고한다(사용자가 터미널 탭에서 허용). 폴더가 없으면 기록 없이 띄운다 (spawn 이 실패한다). 외부(터미널·IDE) 세션이나 호스트에 직접 spawn 하는 시험에서는 여전히 창이 뜨고, Enter 만 보내면 종료 코드 1로 죽는 게 정상이다
- **모델·effort 바꾸기 (근무 중인 웹 세션만).** 세션 안에서 `/model`·`/effort` 를 pty 로 보내면 그 세션만이 아니라 사용자 전역 `~/.claude/settings.json` 의 기본값까지 바뀌어서(실측, Claude Code 2.1.310) 쓰지 않는다. 대신 hq 기록 extraArgs 의 `--model`·`--effort` 를 바꾸고 claude 를 끈 뒤 `--resume <id> … --model X [--effort Y]` 로 다시 띄운다 (`PUT /api/sessions/:id/model` → 호스트 `restart-session`). 퇴근으로 가지 않고 근무 그대로이며(호스트 목록에서 빠지는 순간이 없다), 대화·세션 ID·이름·팀장 지침·`--mcp-config`·권한 모드 같은 다른 인자는 그대로 이어지고 바꾼 값은 이후의 resume(호스트 재시작·다시 출근)에도 남는다. 인자 없이 resume 하면 모델은 jsonl 마지막 응답의 모델, effort 는 전역 설정(`modelSettings[모델].effortLevel`) → 모델 기본값이라(실측) model 은 늘 넘기고(null 은 400 — "기본값" 이 뜻이 없다) effort null 은 `--effort` 를 빼서 전역 설정을 따르게 한다. 모델을 바꾸면 다음 차례에 프롬프트 캐시가 전부 미스 나 문맥 전체를 다시 쓴다(그래서 목록에 `contextTokens` 를 싣는다). effort 만 바꾸면 지금 모델 4개에서는 캐시가 유지된다(실측). 끄면 사라지는 것이 있으면 409: 작업 중·승인 대기, 붙잡은 질문, 대기 메시지(`queuedPrompts` — 대기열은 프로세스 메모리에만 있다), 도는 백그라운드 shell("…background shells are running")·백그라운드로 넘어간 MCP 호출·백그라운드 에이전트("…background tasks are running", `runningBackgroundTasks`), 대기 메시지 취소·작업 중지 진행 중, jsonl 없음(대화가 한 번도 없으면 resume 할 수 없고 끄면 기록이 지워진다). 훅 상태가 unknown(서버 재시작 직후)이면 작업 중인지 몰라 막지 않고, 모니터는 보지 않는다 (끄면 같이 끝난다). 비교는 hq 기록 값끼리라 기록에 `--model` 이 없는 세션(팀장·사람이 만든 세션)은 jsonl 의 모델과 같은 것을 골라도 한 번 다시 띄운다. 끌 때 SessionEnd 훅이 와서 다시 뜬 뒤 상태는 근무 중 ended → my-turn·idle 로 보인다 (`displayStatus`, 호스트 재시작과 같다)

## 확인하지 못한 것

- 모델·effort 바꾸기 서버·호스트 쪽은 단위 테스트와 시험 서버 + claude 대신 `cmd.exe` 를 띄운 시험 호스트(임시 홈·가짜 pipe·포트 4792)로만 확인했다: 400·404(없는 세션·퇴근 세션)·409(첫 대화 전·작업 중·승인 대기·질문·대기 메시지·백그라운드 shell)·503·200 false·true, 기록 extraArgs 교체(팀원은 그 자리, 팀장은 지침·`--mcp-config` 뒤에 붙음, effort null 은 `--effort` 빠짐), 퇴근으로 가지 않고 새 프로세스로 resume(새 명령줄 끝이 `--model … --effort …`, 옛 프로세스 끝남), 그 뒤 종료 버튼은 평소대로 dismissed 퇴근, 프로세스 없는 세션의 `restart-session` 은 error·hq.json 그대로. 실행 중인 서버·호스트에서 화면 모델 칩으로 실제 팀장 세션의 effort 를 바꿔 claude 가 바뀐 인자로 다시 뜨고 MCP 도구(`team_status`)가 다시 붙는 것까지 확인했다. 모델(effort 가 아니라 모델 자체)을 바꾼 실제 확인은 보지 못했다 (실제 세션을 다시 띄워야 해서 남긴다. 대기 메시지 취소·작업 중지 진행 중 409 는 `modelChangeConflict` 가 `unqueues`·`interrupts` 를 보는 것을 코드로 확인했다)
- 질문을 붙잡은 채 서버를 재시작했을 때 (연결이 끊겨 훅이 non-blocking 오류가 되고 터미널 질문 화면만 남을 것으로 예상). 질문 카드의 [Submit]·[Chat about this] 버튼 클릭 자체와 preview 가 있는 실제 질문 (같은 요청을 API 로 보내 확인했고, [Cancel] 는 실제 화면에서 눌러 deny 로 들어갔다) — 실제 claude 질문과 서버 재시작이 같이 필요해 오래 걸려 남긴다
- 다른 PC 에서 실제 접속 (방화벽 허용 여부). 서버 쪽 인증 흐름은 이 PC 의 LAN IP 로 검증했다 (다른 PC 가 없어 남긴다)
- 대화 API 캐시·증분(`messageCache.ts`)은 단위 테스트, 실제 jsonl 사본 검증, 시험 서버(임시 홈·가짜 pipe·포트 4795, 173MB jsonl 사본)로만 확인했다. 검증: 실제 세션 10개(대기열·압축·지시 from·가장 큰 것 포함)를 줄 단위·줄 중간에서 끊어 17,668번 늘려 가며 서버 캐시 결과와 화면이 이어 붙인 결과가 매번 전체 parse 와 같음(불일치 0, 그중 앞 메시지가 바뀐 증분 3,356번). 줄 단계로 나눈 `parseMessages`·`queuedPrompts` 는 실제 jsonl 288개(2GB)에서 옛 것과 같음. 시험 서버 측정(이 PC 안 요청, br): 옛 코드는 처음 683ms·다시 받기 686ms·304 도 588ms(매번 다시 해석)·줄 3개 추가 뒤 636ms·1.09MB, 새 코드는 처음 561ms·같은 것 다시 받기 79ms(5.9MB br 압축)·304 12ms·since 변경 없음 13ms·98B·줄 3개 추가 뒤 31ms·약 0.1~0.8KB (HTTP 로 이어 붙인 결과 == 전체 받기 10번 모두). 실행 중인 서버(트레이)에서는 GET 만으로 일하는 팀장 세션(76 메시지)의 처음 받기 50KB 5ms·ETag 304 2ms·since 변경 없음 94B 를 확인했다. 여러 화면이 같은 세션을 볼 때·서버 메모리가 실제로 얼마나 느는지는 보지 못했다 (오래 지켜봐야 해서 남긴다)
- 저장 API 는 단위 테스트와 시험 서버(임시 홈·가짜 pipe·4796, `bind 0.0.0.0`, 임시 git 작업 폴더)로만 확인했다: CRLF·BOM+CRLF·LF 보존(바이트), 409, EUC-KR 422, `.git`·`.GIT` 403, 밖·없음·폴더 404, 절대 경로 400, 다른 Origin·"null"·없음·rebinding Host 403, Referer 만 통과, text/plain 415, 1MB 초과 413, 읽기 전용 500(원본 그대로), 이 PC 의 LAN 주소로 쿠키 없이 401·쿠키 있으면 GET 다른 PC 이유·PUT 403(Origin·Host 를 속여도, X-Forwarded-For 127.0.0.1 이어도). 실제 다른 PC, 방화벽 허용 창(뜨지 않았다), 잠긴 파일(EBUSY)·디스크 가득·되돌리기, 실행 중인 서버는 보지 못했다 (다른 PC·실제 파일 잠금이 필요해 남긴다)
- 대화 속 그림 API 는 단위 테스트와 시험 서버(임시 홈·가짜 pipe·4799, 이 저장소를 cwd 로 한 휴식 웹 세션)로만 확인했다: 저장소 안 절대(`\@private` 포함)·상대·SVG(CSP sandbox)·scratchpad 그림 200(바이트 같음, 압축 없음), 없음·밖 절대·`../` 밖·글 파일·폴더 404, `C:x`·`a:s`·NUL·path 없음·배열·세션 ID 꼴 400. 실행 중인 서버·다른 PC 는 보지 못했다
- 세션 작업 폴더 API 는 단위 테스트와 시험 서버(임시 홈·가짜 pipe·포트 4796, 이 저장소를 cwd 로 한 근무 웹·휴식·퇴근·외부 pid 기록·없는 폴더 가짜 세션)로만 확인했다: tree·file·file/raw·find 의 200·400(꼴)·404(없는 세션·없는 폴더·`..`·밖을 가리키는 junction·폴더/파일 종류 틀림·그림 아님), sha1 이 `sha1sum` 과 같음, png binary·electron.exe too-large. 실행 중인 서버(트레이)에서는 GET `tree` 200 만 봤다. 다른 PC 접속·EUC-KR 실제 소스(단위 테스트만)·권한 없는 폴더는 보지 못했다
