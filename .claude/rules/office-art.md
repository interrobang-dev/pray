# 도트 스프라이트·인물 그림

목록 아바타·도트 인물 고르기·색 바꾸기, 스프라이트 파이프라인(`tools/sprites/`)과 그 결과 아틀라스(`web/public/office/`)를 다룬다.

원래 루트 `CLAUDE.md` 한 파일이던 내용을 옮긴 것이다. 본문의 "위·아래 …"·"핵심 개념 …" 은 그때의 말이라 가리키는 항목이 다른 파일에 있을 수 있다. 어디서나 지킬 규칙·근무·휴식·퇴근·표시 상태·실행 방법은 루트 `CLAUDE.md`, 다른 영역은 루트의 문서 지도를 본다. 이 영역을 고치면 이 파일의 그 줄을 고쳐 쓴다.

다른 파일에 있는 항목:
- "퇴근 거리" → office.md
- 캔버스에서 인물을 그리는 쪽(Office.tsx) → office.md

## 핵심 개념

- **새 세션 인물 자동 배정** (팀장이 10명 가까이 되어 해시만으로는 겹친다). 서버가 `POST /api/sessions`·팀원 spawn 때만 인물을 골라 `hq.json.characters[id] = { id, hair, top, isAuto: true }` 로 저장한다. 기존 세션·resume·외부 세션은 건드리지 않는다(저장이 없으면 화면이 해시). 후보는 해시와 같다(역할과 상관없이 전체. 성별은 서버가 이름을 지을 때 정한 것, 없으면 무시). 그중 ① 근무·휴식 세션(퇴근 제외, 외부 포함)이 지금 보이는 인물(`charactersInUse` = `dotLookOf`: 고른 것·배정·없으면 해시)과 방금 배정해 아직 목록에 없는 것(서버 메모리 60초, 팀원을 연달아 띄울 때)에서 가장 적게 쓰인 것 ② 같으면 같은 팀이 안 쓰는 것 ③ 그래도 같으면 세션 ID 해시. 고른 인물을 이미 누가 쓰면 그 세션들의 (머리, 윗옷) 과 다른 색: 기본색(null, null)이 비었으면 그것, 아니면 `HAIR_COLORS × TOP_COLORS` 80조합을 세션 ID 해시로 섞은 순서(`shuffledCombos`, mulberry32 시드 + Fisher–Yates — 차례대로면 다시 뽑을 때 머리색이 그대로라 비슷해 보였다. 시드라 화면 미리보기와 서버 배정이 같다)에서 처음 빈 것(다 차면 그 순서의 첫 것). 그래서 18명(성별이 있으면 그 성별 9명)이 한 번씩 다 쓰인 뒤부터 색이 붙는다
- 인물 목록은 서버가 `web/public/office/office-v5-down.json` 의 `meta.jkCorp.characters` 에서 읽는다 (`server/src/character.ts` 의 `makeCharacterSheetReader`, 수정 시각·크기가 그대로면 앞 결과. 빌드 결과가 아니라 원본이라 `web/dist` 없이도 된다). 없거나 해석이 안 되면 배정하지 않는다(로그는 실패·복구로 바뀔 때만)
- 직접 고른 인물(`isAuto` 없음)이 이긴다. "Auto" 로 되돌리면(`{ id: null }`) 지운 뒤 해시로 가지 않고 그때 목록으로 **새로 배정**한다 (자기 자신은 빼고 센다. 직접 고르기 전 배정은 남겨 두지 않아서). 목록에 없는 세션·아틀라스를 못 읽으면 지운다. 옛 코드는 `isAuto` 를 모르고 인물·색으로 그대로 쓴다 (옛 화면의 고르기 창은 배정을 고른 인물로 보인다). `readHq` 가 키를 보존하고, 호스트가 이름과 같이 지우는 것도 같은 `characters` 라 옛 호스트에서도 같이 지워진다
- 팀원 spawn 은 인물을 호스트에 spawn 을 보내기 **전에** 쓴다 (못 보내면 지운다). 뒤에 쓰면 호스트가 같은 때 `webSessions` 를 쓰며 덮어써 사라진다 — 시험 서버에서 팀원을 쉬지 않고 연달아 띄우면 spawn 뒤에 쓰는 이름·역할·성별이 8명 중 5명꼴로 사라졌다(호스트 쓰기의 rename 재시도로 창이 길어지는 것으로 짐작). 1.5초 간격이면 다 남았다

- **색 바꾸기 규칙** (`web/src/recolor.ts`, 트레이 사본 `desktop/src/recolor.ts` — 고치면 둘 다, `desktop/src/recolor.test.ts` 가 같은 결과인지 본다): 바꾼 색 = 고른 색의 색상·채도 + 고른 색 밝기 + (픽셀 밝기 − 기본색 밝기) × 배율(고른 색 밝기 / 기본색 밝기, 0.6~3). 기본색보다 밝은 쪽은 고른 색 밝기에서 1 까지 남은 여유 안에 `여유 × (1 − e^(−차이/여유))` 로 눌러 담는다 — 그냥 더하면 밝은 색을 고를 때 하이라이트가 흰색으로 날아갔다. 어두운 쪽은 배율만. 기본색(null)이면 마스크를 아예 안 쓴다(그림이 픽셀 단위로 그대로). 그래서 **기본색이 실제 부위 색과 어긋나면 결과가 하얗게·까맣게 뜬다** — 기본색은 마스크 JSON 의 값이다
- **색 바꾸기 마스크** (`mask.py`, 머리말에 전문): 인물마다 idle 첫 칸의 표본 상자(`sample`) 색을 모으고, 그 인물의 모든 칸에서 세로 범위(`y`) 안이면서 표본 색과 가까운(`tolerance`) 픽셀을 고른다. 외곽선(가장 밝은 채널 `outlineMax` 기본 26 이하)·표본의 드문 색(`minShare` 기본 0.04 미만)·`exclude` 상자·10픽셀 미만 덩어리는 뺀다. v5 레시피는 맨 위 `"method": 2`: ① 기본색 = 표본 픽셀 수 기준 채널별 가운데 값 (옛 규칙은 고유 색의 가운데라 외곽선 쪽 변종에 끌려, overalls 머리 기본색이 #1f090d(실제 #eb7782)가 되어 밝기 배율 3 으로 하얗게 날아갔다. 정면 36칸 중 32칸의 기본색이 바뀌었다) ② 부위 경쟁: 머리·윗옷·피부(인물 단위 `skin` 상자) 표본 중 자기 표본이 가장 가까운 픽셀만 (같으면 진다) ③ 가중치 0/1 (거리 tolerance×0.8 미만). `method` 가 없는 v1·v3 레시피는 옛 규칙 그대로 (결과가 바이트 단위로 같다. 화면은 안 읽지만 다시 돌려도 안 바뀌게). 방향 판(up·right)은 `--sample-atlas` 로 정면 판에서 `sample`·`skin` 을 모으고, 정면 표본이 그 방향 팔레트와 안 맞으면 `sampleSelf`·`skinSelf`(그 방향 idle 첫 칸 좌표, 대신 씀)·`sampleAdd`(더함)를 쓴다. `sampleFrames` (`{"raise-hand/0": [상자]}`) 는 그 칸에서 고를 색만 더한다(기본색에는 안 넣음). `compete`: `false` 면 경쟁 안 함, `"share"` 면 머리·윗옷이 같은 색으로 맞설 때 표본 안 비율이 큰 쪽이 갖고 그다음 주변 7×7 다수결로 정한다 (lead-suit 세 방향: 검은 머리 하이라이트와 회색 정장이 팔레트 색을 나눠 써서 보통 경쟁이면 정장이 통째로 빠지고, 세로 범위로 가르면 고개 숙인 칸 어깨·든 팔 소매가 머리가 됐다)
  - 함정 ① **상태 행(typing·raise-hand·doze)은 따로 생성돼 같은 부위도 팔레트 색이 idle 과 다르다** (hijab 정면 typing 스카프 #e88679 ↔ idle #d26458). idle 표본만으로는 그 칸이 빠진다 → `sampleFrames`. ② **`y`·`exclude` 는 칸마다 같은 셀 좌표라 idle 기준으로 잡으면 다른 칸에서 깨진다** — 든 팔 소매가 윗옷 `y` 위로 나가고(headphones·hoodie·braids 등), 얼굴 exclude 가 고개 숙인 칸의 머리·옮겨 간 블레이저를 지운다(hijab 옆 doze, lead-blazer 정면 raise-hand). 얼굴은 exclude 보다 `skin`/`skinSelf` 경쟁으로 막는 편이 칸 이동에 강하다. ③ 피부·셔츠 음영과 같은 색을 표본에 넣으면 다른 칸의 팔·얼굴이 잡힌다 (polo 셔츠 음영 #b8682a 를 넣으니 typing 팔뚝이, professor raise-hand 흰 옆머리를 넣으니 모든 칸 얼굴이 머리가 됐다). 상자 안 색은 먼저 찍어 보고 넣는다
  - 레시피를 고치면 세 방향 마스크를 다시 만들고(아틀라스만 있으면 된다. 생성 원본 불필요), **idle 만이 아니라 18명 × 세 방향 × 모든 칸**에 마스크를 칠해 본다 (`--preview` 는 idle·raise-hand 첫 칸뿐). 지금 남은 것: polo 정면 셔츠의 주황 음영선(그 색이 다른 칸 팔 피부색과 같아 못 넣음)·hijab 정면 raise-hand 의 든 베이지 소매(피부색과 같음)·professor 정면 raise-hand 흰 옆머리·flannel 정면 doze/0 그늘진 갈색 머리·lead-vest 옆 typing 등 쪽 짙은 빨강·afro 뒷모습 아래쪽 거의 검은 머리(외곽선 한도에 걸림) 같은 작은 잔점

## 확인하지 못한 것

- 자동 배정은 단위 테스트와 시험 서버(임시 홈의 가짜 hq·팀 7개, cmd.exe 대역 시험 호스트, 가짜 pipe·포트 4797) + Vite 4798 headless Chrome 화면으로만 확인했다. 실제 팀장의 `team_spawn_member` 로 새 세션에 배정되는 것은 보지 못했다 (세션을 만드는 쓰기). 실행 중인 서버의 폰 목록 아바타(`npm run shot --phone`)는 이상 없었다

- 도트 인물 18명은 가짜 API 로만 봤다 (정면은 v3 때 2750×1700 1배 인물별 4상태, 4방향 v5 는 섬·부스 안에서 몇 명씩. 고른 색은 옆모습·정면·뒷모습 한 명씩 2배). 18명 전원의 뒷모습·옆모습 4상태를 사무실 안에서 한 번에 본 것은 아니다. 실행 중인 서버·실제 세션 성별로 고른 인물은 `npm run shot` 사무실·폰 목록 아바타로 이상 없었다
