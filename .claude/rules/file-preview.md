# Files 탭 파일 미리보기 (그림·SVG·HTML·PDF·docx·표·hwp·동영상·소리)

세션 패널 Files 탭 오른쪽 `FileView` 가 글 코드 보기 대신 파일을 그 모양대로 보이는 것과, 그것이 받는 서버 raw 주소 두 꼴(`/file/raw?path=`·`/raw/<경로>`), 그리고 파일을 기기로 받는 주소(`/file/download?path=`)·Copy 메뉴 Download·Share… 를 다룬다. 이 영역을 고치면 이 파일의 그 줄을 고쳐 쓴다.

다른 파일에 있는 항목:
- Files 탭 전체(트리·위 막대·코드 보기·편집·Changes·Search·History) → workspace.md. md 문서 미리보기(`MarkdownDocument`)도 workspace.md
- 작업 폴더 API 공통 규칙(`workspaceRootOf`·`resolveWorkspaceRequest`·`isValidRequestPath`·`resolveWorkspacePath`·인증) → server-api.md
- 이 PC 의 Chrome 으로 열기 API(`POST …/open-in-chrome`, `openInChrome.ts`)·Host·Origin 검사 → security.md
- 작업 파일 창(scratchpad, `Files.tsx`)의 미리보기는 다른 기능이다 → chat.md

## 핵심 개념

- **미리보기 종류** (`filePreview.ts`): 그림(png·jpg·jpeg·gif·webp·bmp·ico·avif)은 `<img>`(`.ws-image` 체크무늬). **SVG** 는 기본이 `<img>` 그림(안의 스크립트가 돌지 않는다. 서버도 CSP sandbox). **HTML**(html·htm)은 기본이 문서 미리보기(아래). **PDF** 는 데스크톱이면 `<iframe>`(Chrome 내장 뷰어, `.ws-frame`), 폭 768px 이하·`(hover: none)`(`NO_PDF_FRAME_QUERY`, 그릴 때 한 번 봄. 안드로이드 Chrome·WebView 는 내장 뷰어가 없다)이면 pdf.js canvas(아래 "폰 PDF"). **동영상**(mp4·m4v·webm·ogv·mov)·**소리**(mp3·wav·ogg·oga·m4a·aac·flac·opus)는 `<video controls>`·`<audio controls>`(`.ws-media`, 칸 안에 비율대로, 소리는 폭 480px 까지), 탐색은 서버 Range(206). **pptx** 는 글을 받지 않고 "No preview for this file type" 만 (받으려면 Copy 메뉴 Download — 아래 "받기". 옛 doc·ppt 는 그대로 글로 받아 "Binary file · No preview"). 그림·PDF·docx·xlsx·xls·hwp·hwpx·동영상·소리·pptx 는 글을 받지 않아(`isRawOnlyKind`) 크기·시각은 트리 목록 값이고 연필·Ctrl+F 가 없다. 모두 ↻ 마다 `v=` 로 다시 받는다
- **폰 PDF** (`PdfPreview`): `/file/raw` 로 받은 바이트를 pdf.js(npm `pdfjs-dist` **정확히 6.5.438** — 올릴 때 web/package.json 의 고정 버전을 바꾸고 `npm install`)로 연다. pdf.js 는 처음 그릴 때만 `import('./pdfDocument')` 해 따로 나뉜 청크(약 470KB)에만 들고, 데스크톱(iframe)은 이 청크를 받지 않는다. **worker** 는 `pdfjs-dist/build/pdf.worker.min.mjs?url` — Vite 가 같은 출처 파일(약 1.27MB)로 내보내 CDN 을 부르지 않는다. **CMap·표준 글꼴·그림 wasm**: pdf.js 는 폴더 주소(`cMapUrl` 등)를 바라지만 Vite 파일 이름에 해시가 붙어, `pdfAssets.ts` 가 `import.meta.glob(…, { query: '?url&no-inline', eager: true })` 로 이름 → 주소 표를 만들고 `useWorkerFetch: false` + `BinaryDataFactory` 로 worker 가 달라는 파일을 그 표에서 준다 (`cMapUrl` 등은 pdf.js 가 값이 있어야 달라고 해서 둔 이름표). 빌드에 cmaps 168개(1.4MB)·standard_fonts·`jbig2.wasm`·`openjpeg.wasm` 이 따로 나가고 **문서가 그 파일을 쓸 때만 받는다** (내장하지 않은 한글 글꼴 `UniKS-UCS2-H` PDF 는 그 bcmap 둘과 `FoxitSymbol.pfb` 만 받았다). glob 경로가 `../../node_modules/pdfjs-dist/…` 라 pdfjs-dist 가 루트 node_modules 에 올라가 있어야 한다 (안 올라가면 표가 비어 그 파일이 필요한 문서만 글자·그림이 빠진다 — 테스트가 잡는다). dev 에서는 eager glob 이 파일마다 모듈 요청을 하나씩 보낸다(빌드 결과는 청크 안 글자). `quickjs`(문서 JavaScript)·`qcms`(ICC 색, `useWorkerFetch: false` 면 pdf.js 가 안 쓴다 — ICC 색은 대체 색 공간으로 그린다)는 내보내지 않는다. **보안**: pdf.js 6 에는 `isEvalSupported` 옵션이 없다 (글꼴에 eval·`new Function` 을 쓰지 않는다 — 빌드 파일에서 확인). 문서 JavaScript 는 pdf.sandbox 를 불러야 도는데 부르지 않고, `enableXfa: false`, 글자 층·주석 층(링크·폼)은 만들지 않는다 (canvas 만 — 그래서 글 고르기·복사·찾기·링크 누르기가 없다. 주석 모양은 `AnnotationMode.ENABLE` 로 canvas 에 그린다). `disableWorkerRendering: true`(renderer worker 를 쓰지 않고 메인 스레드에서 그린다). **크기 상한 50MB** (`PDF_PREVIEW_LIMIT_BYTES`): Content-Length 로 받기 전에 끊고 "Too large to preview · 51.0 MB (limit 50 MB)" — 해석은 worker 라 화면이 멈추지 않지만 폰 망으로 받는 시간과 worker 가 통째로 쥐는 메모리 때문 (도면 스캔 PDF 가 수십 MB 라 docx 20MB 보다 크게 잡았다). 받는 중 "Loading…", 못 열면 "Couldn't open the PDF", 암호가 걸리면 "Password-protected PDF · No preview". **그리기**: 쪽 목록·확대는 아래 "쪽 단위 보기". 쪽마다 새 canvas 에 그려 끝나면 바꿔 끼우고(그리는 동안 앞 canvas 가 남는다) 폭이 바뀌면(확대·창 크기) 다시 그리고, 멀어지면 canvas 를 버리고 `page.cleanup()`. canvas 배율 = `devicePixelRatio`(상한 3), 쪽 하나가 800만 화소(약 32MB)를 넘으면 배율을 낮춘다 (S26 맞춤 1032×1460, 300% 확대 390 폭 화면 2244×3175). 원본 전환·연필·Ctrl+F 없음, ↻ 마다 다시 받는다
- **쪽 단위 보기** (`PagedView`, 폰 PDF·hwp·hwpx 공용): 위 막대 `.ws-paged-bar` = 왼쪽 "Page 3 of 12"(보기 세로 가운데가 든 쪽, 스크롤마다 한 프레임에 한 번) · 오른쪽 − · "100%"(누르면 칸 폭 맞춤, title "Fit to width") · +. 확대 단계 100·125·150·200·300% (`ZOOM_STEPS`, 100% = 칸 폭 − 양옆 8px 에 쪽 폭을 맞춤, 쪽마다 폭을 맞춰 가로 쪽은 낮다. 그리기 전에 여러 번 눌러도 단계마다 넘어간다), 바꾸면 보던 가운데 자리를 지키고 칸보다 넓으면 가로 스크롤 (`.ws-paged-pages` 가 `width: max-content` — flex 가운데 맞춤이면 왼쪽 넘친 부분에 못 간다). 핀치 확대는 따로 만들지 않았다 (+ − 로 충분하다고 봤다. 브라우저 페이지 확대는 그대로). 아래 `.ws-paged-scroll`(`--surface-1`) 안에 쪽마다 자리 `.ws-paged-page`(흰 바탕 `#fff`·`--shadow-pop`, 크기를 모르는 쪽은 첫 쪽 비율로 자리를 잡고 그리면 그 쪽 크기로)를 두고 **IntersectionObserver(보기 위아래 한 화면, `rootMargin: 100% 0px`)에 걸친 쪽만** `drawPage` 로 그리고, 멀어지면 비우고 `releasePage`. `isScalable`(늘려도 선명한 SVG) 이면 확대·폭이 바뀌어도 다시 그리지 않는다. `drawPage`·`releasePage` 는 `useCallback` 으로 고정해 넘긴다 (바뀌면 보이는 쪽을 다시 그린다). 폰 막대 버튼 40px
- **hwp·hwpx 미리보기** (`HwpPreview`, 폰·데스크톱 같다): `/file/raw` 로 받은 바이트를 rhwp(npm `@rhwp/core` **정확히 0.9.1**, MIT, Rust+WASM — HWP 5.0·HWPX·일부 HWP 3.0 을 쪽마다 SVG 로)로 연다. 처음 그릴 때만 `import('./hwpDocument')` 해 따로 나뉜 청크(약 143KB)에만 들고, **wasm `rhwp_bg.wasm` 은 `@rhwp/core/rhwp_bg.wasm?url` 로 Vite 가 같은 출처 파일로 내보낸다 — 27.9MB(서버 compression 으로 gzip 약 10.6MB 전송), 처음 hwp 를 열 때 한 번 받고 그 뒤는 ETag 로 다시 받지 않는다**. 0.8.7 은 wasm 11.8MB(gzip 4.4MB)지만 0.9.x 의 중첩 표·글꼴 조판 보정을 위해 0.9.1 로 정했다 (0.9.0 부터 PDF 가져오기·JBIG2·JPEG 2000·ICC 가 기본으로 들어 커졌다 — 이 화면은 쓰지 않는다). 올릴 때는 web/package.json 고정 버전을 바꾸고 `npm install`, 타입 정의 `rhwp.d.ts` 의 `HwpDocument`(생성자·`pageCount`·`getPageInfo`·`renderPageSvg`·`free`)를 다시 본다. **글자 폭**: README 는 `globalThis.measureTextWidth` 를 등록하라지만 0.9.1 은 그 이름을 쓰지 않고(js·wasm 어디에도 없다) 스스로 canvas 를 만들어 `measureText` 를 부른다 — 그래서 등록하지 않는다. 같은 이유로 문서를 메인 스레드에서 연다(worker 에 DOM 이 없다). **SVG 는 앱 DOM 에 innerHTML 로 넣지 않는다** — 쪽마다 `renderPageSvg` 결과를 `Blob(image/svg+xml)` → blob 주소 `<img>` 로 보인다 (img 안 SVG 는 스크립트가 돌지 않고 바깥 주소를 부르지 않는다). 읽어 들인 뒤 blob 주소는 놓는다 (확대해도 다시 받지 않는다). 실측(샘플 다섯): SVG 에 `<script>`·`foreignObject`·바깥 href·`url(…)`·`@font-face` 없음, 그림은 `data:image/jpeg`·`data:image/svg+xml` data URI 로 들어 img 안에서 그대로 나온다(같은 쪽을 rhwp 의 `renderPageToCanvas` 로 그리면 그림이 빠진 빈 쪽이었다 — 그래서 canvas 가 아니라 SVG 다). 글꼴은 SVG 의 `font-family` 목록(원래 글꼴 → 맑은 고딕·Apple SD Gothic Neo·Noto Sans KR·Noto Sans CJK KR·Pretendard·함초롬 … → sans-serif/serif)을 **그 기기에 설치된 글꼴로** 푼다 — img 안 SVG 는 앱이 불러온 웹 글꼴(Pretendard Variable·Fraunces)을 못 쓰지만, 목록에 그 이름이 없어 rhwp 가 글자 폭을 잰 canvas 와 같은 시스템 글꼴로 풀린다. 쪽 크기는 `getPageInfo` 의 `width`·`height`(96dpi px, A4 793.7×1122.5), 모르면 A4 로 자리를 잡고 그린 뒤 img 의 원래 크기로 고친다. 쪽 SVG 는 가까워질 때 쪽마다 `setTimeout` 으로 미뤄 만든다 (한 쪽 수~80ms, 그림이 많은 쪽은 더). **크기 상한 30MB** (`HWP_PREVIEW_LIMIT_BYTES`): Content-Length 로 받기 전에 끊고 "Too large to preview · 31.0 MB (limit 30 MB)" — rhwp 가 메인 스레드에서 통째로 풀고 쪽 SVG 마다 그림을 base64 로 다시 넣어 메모리가 몇 배가 된다 (사진 든 현장 보고서를 생각해 docx 20MB 보다 크게). 받는 중 "Loading…", 못 열면 "Couldn't open the document"(rhwp 오류 글은 한국어라 보이지 않는다), 암호 문서는 rhwp 가 "비밀번호가 필요한 암호 문서입니다 …" 로 알려 그 글로 가려 "Password-protected document · No preview" (암호는 묻지 않는다). 문서는 불러오기 effect 가 끝날 때(다른 파일·↻·닫기) `free()` — 목록 쪽 effect 에서 놓으면 dev StrictMode 의 이중 effect 로 먼저 놓여 다음 그리기에서 "null pointer passed to rust" 로 화면이 죽었다. 원본 전환·연필·Ctrl+F·글 고르기 없음, ↻ 마다 다시 받는다
- **미리보기 ↔ 원본 전환 (SVG·HTML·csv)**: 위 막대의 md 와 같은 전환 버튼(`.ws-md-toggle`, 눈 "Show preview" ↔ 꺾쇠 "Show source")으로 원본(`CodeView` — 편집·Ctrl+F·줄 고르기)이 된다. 그래서 둘은 글도 받아 둔다. 원본 여부는 `sessionViews` 의 `sourceViews`(`{ svg, html, csv }`, md 의 `isMarkdownSource` 와 따로)에 종류마다 남는다. 미리보기 중(`isRenderedPreview`)에는 md 미리보기처럼 줄이 없어 경로 표시줄 ":12"·Add to chat 줄이 없고 Ctrl+F 를 가로채지 않는다. 글로 못 받은 것(1MB 초과·NUL)은 원본을 보일 수 없어 늘 미리보기다. Search 결과 줄·대화 속 `경로:줄` 로 열면 원본으로 바꾼다
- **HTML 미리보기**: `<iframe class="ws-html-frame" sandbox="allow-same-origin">` 가 `rawPathUrl` 주소(`/api/sessions/<id>/raw/site/index.html?v=0`)를 연다. **sandbox 에는 `allow-same-origin` 하나만 — allow-scripts·allow-forms·allow-popups·allow-top-navigation 등은 넣지 않는다**. 스크립트가 돌면 로컬 접속은 무인증이라 문서가 `/api` 를 불러 세션 조작까지 된다. 서버도 이 주소의 HTML 에 `Content-Security-Policy: sandbox allow-same-origin` 을 붙여 주소를 새 탭으로 직접 열어도 스크립트가 돌지 않는다 (Chrome 콘솔 "Blocked script execution … 'allow-scripts' permission is not set"). **`allow-same-origin` 을 주는 이유**: 출처가 null(opaque)이면 메일 로그인한 다른 PC 에서 문서가 부르는 CSS·그림·글꼴 요청에 SameSite=Lax 쿠키 `jk_session` 이 안 붙어 401 이었다 (문서 요청 자체는 앱 화면이 연 iframe 이라 붙는다). 같은 출처여도 스크립트·폼·팝업·위 창 이동이 막혀 있어 문서가 할 수 있는 것은 `<img>`·`<link>` 같은 GET 뿐이고, GET 은 상태를 바꾸지 않는다 (→ security.md "CSRF 막기의 범위"). 문서 안 iframe·`<meta http-equiv=refresh>` 로 옮겨 간 문서도 같은 sandbox 를 물려받는다. 그래서 앱 쪽에서 `contentDocument` 를 읽을 수 있다 (시험·확인용). 작업 파일 창(`Files.tsx`·scratchpad raw)의 HTML 은 따로 `sandbox=""`·CSP `sandbox` 그대로다. 주소에 경로가 그대로 들어 있어 문서 안 상대 경로(`css/site.css`·`img/a.png`·`../logo.svg`·CSS 안 `url(../fonts/x.woff2)`)가 같은 꼴 주소로 풀려 불러와진다. `/` 로 시작하는 경로(`/style.css`)는 앱 주소 맨 위로 풀려 안 된다. 바탕은 다크에서도 흰색 `#fff`(HTML 은 흰 바탕을 전제 — 작업 파일 미리보기와 같은 테마 예외, → theme.md). 폴더 주소(`/raw/site/`)는 400 이라 `index.html` 을 저절로 찾지 않는다
- **docx 미리보기** (`DocxPreview`): `/file/raw` 로 받은 바이트를 mammoth(`mammoth` npm 의 lib 를 Vite 가 package.json `browser` 필드로 묶은 것. 처음 그릴 때만 `import('mammoth')` — 따로 나뉜 청크(약 310KB)라 메인 번들에 안 든다. `CodeEditor` 의 CodeMirror 와 같은 꼴)로 HTML 로 바꿔 `<iframe class="ws-doc-frame" sandbox="" srcdoc>` 에 넣는다. **앱 DOM 에 innerHTML 로 넣지 않는다** (문서 HTML 이 앱 출처에서 돌면 `/api` 를 부를 수 있다). sandbox 가 빈 값(allow-same-origin 도 없음 — 하위 요청이 없어 쿠키가 필요 없다)이라 출처가 null 이고 스크립트가 안 돈다. srcdoc 안 CSP `default-src 'none'; img-src data:; style-src 'unsafe-inline'` 라 바깥 주소를 아무것도 부르지 않는다 (mammoth 는 문서 속 그림을 data URI 로 넣고, `externalFileAccess` 기본 false 라 바깥 파일 링크 그림은 읽지 않는다). 바깥 링크는 href 를 떼고 주소를 title 로 남긴다 — iframe 안에서 누르면 그 자리가 다른 사이트로 바뀌기만 해서다 (`#` 문서 안 링크·각주는 그대로). 흰 바탕·검은 글자·표 테두리·그림 폭 맞춤은 srcdoc 안 `<style>` 이 정한다 (HTML 미리보기와 같은 테마 예외, 칸 바탕도 `.ws-doc-frame` `#fff`). mammoth 는 문서 구조(제목·굵게·기울임·목록·표·그림·각주)만 옮기고 글꼴·색·크기·쪽 나눔·머리글·도형은 버린다. **크기 상한 20MB**: 응답 Content-Length 가 넘으면 받다 말고, 받은 뒤에도 넘으면 "Too large to preview · 21.0 MB (limit 20 MB)" — mammoth 가 메인 스레드에서 zip·XML 을 풀어 큰 파일은 화면이 오래 멈춘다. 받는 중 "Loading…", 받기·해석 실패(zip 아님·HTTP 오류) "Couldn't open the document". 원본 전환·연필·Ctrl+F 없음, ↻ 마다 다시 받아 다시 바꾼다
- **표 미리보기 (xlsx·xls·csv·tsv)** — 공용 `SheetTable`: 맨 위 열 문자 줄(A, B, …, Z, AA)·왼쪽 행 번호·첫 줄(머리로 쓰는 줄이라 굵게)이 붙어 있고(`position: sticky`. 첫 줄의 top 이 열 문자 줄 높이와 같아야 해서 두 줄 모두 칸 높이를 `24px × --font-scale` 로 고정한다) 칸 폭을 넘으면 표만 가로·세로로 스크롤한다. 칸은 한 줄(`nowrap`)·320px 까지 말줄임이고 30자 이상·줄바꿈이 든 칸은 title 로 전체를 보인다. 숫자처럼 보이는 글(`isNumberText`: 1,234·-3.5·12%·1e5)은 오른쪽 맞춤. **칸 값은 React 글자로만 그린다** — SheetJS `sheet_to_html`·innerHTML 을 쓰지 않는다 (칸 글이 앱 출처의 HTML 이 되면 안 된다). **그리는 상한: 시트마다 앞 1,000줄·100칸** (`TABLE_ROW_LIMIT`·`TABLE_COLUMN_LIMIT`. 칸이 수십만 개면 화면이 멈춘다), 넘으면 표 아래 "Showing first 1,000 of 1,500 rows · 100 of 240 columns". 색은 기존 변수(`--line`·`--panel`·`--pre-bg`·`--muted`·`--accent-soft`)만 쓴다
  - **xlsx·xls** (`WorkbookPreview`): `/file/raw` 로 받아 SheetJS 로 푼다. SheetJS 는 `workbookSheets.ts` 를 처음 그릴 때만 동적 import 해 따로 나뉜 청크(약 366KB)에만 든다. **SheetJS 는 npm 의 `xlsx@0.18.5`(2022, 프로토타입 오염 CVE-2023-30533·ReDoS CVE-2024-22363 이 고쳐지지 않은 마지막 npm 판)가 아니라 공식 배포 tarball `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz` 를 web/package.json 에 주소로 고정한다** (SheetJS 가 npm 에 더 올리지 않는다. 0.20.3 이 이 주소의 최신 — 올릴 때는 주소의 버전을 바꾸고 `npm install`. lock 의 integrity 로 같은 파일만 받는다. 설치·CI 는 cdn.sheetjs.com 에 닿아야 한다). `read(…, { sheetRows: 1000 })` 로 시트마다 앞 줄만 풀고 전체 크기는 `!fullref` 로 안다. 칸 글은 `sheet_to_json(header: 1, raw: false)` — 셀 서식대로 만든 글이라 날짜(`yyyy-mm-dd` 등 그 셀 서식)·`#,##0`·`0.0%` 가 엑셀처럼 보이고 빈 칸은 빈 글이다. 수식은 저장된 값. 시트가 둘 이상이면 표 위 칩(`.ws-sheet-tabs`, 고른 것 강조색)으로 고른다 (숨긴 시트도 보인다. 고른 시트는 그 파일을 보는 동안만). 시트가 비면 "Empty sheet", 시트 범위가 C3 부터면 행 번호·열 문자도 3·C 부터. **크기 상한 10MB** (`SPREADSHEET_LIMIT_BYTES`): Content-Length 로 받기 전에 끊고 "Too large to preview · 11.0 MB (limit 10 MB)" — SheetJS 가 메인 스레드에서 통째로 푼다. 받는 중 "Loading…", 못 풀면 "Couldn't open the spreadsheet". SheetJS 는 형식을 내용으로 판단해, 확장자만 xlsx·xls 인 글·HTML 파일(사내 프로그램이 내보내는 HTML 표 .xls 등)도 표로 보인다. 원본 전환·연필 없음
  - **csv·tsv** (`DelimitedTable`): 지금처럼 file API 로 글을 받아(EUC-KR 도 풀린다) 그 글을 `parseDelimited` 로 표로 — SheetJS 를 불러오지 않는다. 구분자는 확장자(tsv 탭, 그 밖 쉼표. 세미콜론 csv 는 한 칸으로 보인다). 따옴표 칸 안의 구분자·줄바꿈, `""` → `"`, 따옴표로 시작하지 않은 칸의 따옴표는 글자, LF·CRLF·CR, 앞 BOM. 기본이 표이고 위 막대 전환 버튼으로 원본(`CodeView` — 편집·Ctrl+F·줄 고르기)이 된다 (`sourceViews.csv`). 1MB 넘거나 NUL 이 든 csv 는 글로 못 받아 지금처럼 "Too large to show"·"Binary file" (원본 전환도 없다)
- **Open in Chrome** (위 막대 `.ws-open-chrome`, 상자 밖 화살표 아이콘, title "Open in Chrome: <Windows 전체 경로>"): HTML 파일을 Files·Search 쪽에서 볼 때, **이 PC 화면(`isLocal`)에만** 있다 — 다른 PC·폰은 Show in folder 처럼 그리지 않는다. 대화 속 .html 링크와 같은 `openInChrome`(web `openPath.ts`) → `POST …/open-in-chrome` `{ path: <cwd 상대 경로> }`(서버 규칙 → security.md `openInChrome.ts`). 실패는 알림 창 "Couldn't open in Chrome: …". 스크립트까지 돌려 봐야 하는 문서는 이것으로 연다 (file:// 로 열려 이 앱과 무관하다)

### raw 주소

- **`GET /api/sessions/:id/file/raw?path=`** — Files 탭 그림·SVG·PDF·동영상·소리·docx·xlsx·xls·hwp·hwpx(`isPreviewType`. csv 는 글 API 로 받아 여기를 안 쓴다). 그 밖 404 "No preview for this file type"
- **`GET /api/sessions/:id/raw/<경로>`** — HTML 미리보기용, 경로가 주소 칸에 그대로 든 꼴. 내주는 종류 `isRawAssetType` = HTML(CSP `sandbox allow-same-origin`)·CSS·글꼴(woff·woff2·ttf·otf)·미리보기 종류(그래서 docx·xlsx·xls·hwp·hwpx 도 — 문서로 열리지 않는 형식이라 막을 까닭이 없다). **JS 는 내주지 않는다**(404): iframe 이 sandbox 라 어차피 돌지 않고, 내주면 다른 사이트가 `<script src="http://127.0.0.1:4710/api/…/raw/x.js">` 로 이 PC 의 소스를 끼워 실행할 길만 생긴다 (nosniff 라도 JS 형식이면 돈다). JSON·md·글 파일도 같은 이유로 404 — 문서가 부를 일이 없다. 거절 순서: 경로 칸 `rawRequestPath`(빈 칸 `//`·`.`·`..`·`\`·NUL·콜론 — Express 가 푼 `%2e%2e`·`%2F`·`%5C` 도 다시 나눠 본다) + `isValidRequestPath` 가 틀리면·세션 ID 꼴 400 → 기준 폴더 없음 404 "Session folder not found" → `resolveWorkspacePath`(realpath 가 기준 밖 — 링크·junction 포함)·종류 아님·파일 아님 404 "Not found". 종류는 realpath 의 확장자로 본다 (안쪽 링크 `a.html` → `b.js` 도 404). 기준 폴더·인증은 다른 작업 폴더 API 와 같다(GET 이라 Origin 은 안 본다)
- 두 꼴 모두 머리는 scratchpad raw 와 같다: `X-Content-Type-Options: nosniff`, SVG 는 `Content-Security-Policy: sandbox`(`/raw/<경로>` 의 HTML 만 `sandbox allow-same-origin`), `Cache-Control: no-cache, no-transform`(압축을 꺼 Range 206 이 깨지지 않게). **CORS 머리는 없다** — 문서가 앱과 같은 출처라 글꼴(`@font-face`, 늘 CORS 요청)도 같은 출처 요청이다 (출처가 null 이던 때는 글꼴에 `Access-Control-Allow-Origin: *` 가 필요했다)

### 받기 (Download·Share…)

- **`GET /api/sessions/:id/file/download?path=`** — 세션 cwd 안 파일 하나를 **종류·크기 상관없이** 준다 (미리보기 종류가 아니어도, 1MB 넘어도). 경로 막기는 `resolveWorkspaceRequest(req, res, false)` 그대로: 세션 ID·path 꼴(빈 글·NUL·콜론·`/`·`\` 로 시작) 400, 기준 폴더 없음 404 "Session folder not found", 기준 밖(`..`·밖을 가리키는 링크·junction)·없음 404 "Not found", 폴더 404 "Not a file". 머리 `downloadHeaders`(요청 경로의 마지막 칸이 이름 — realpath 이름이 아니다): `Content-Type: application/octet-stream`, `Content-Disposition: attachment; filename="<ASCII 대체>"; filename*=UTF-8''<percent-encoded>`(대체는 인쇄 가능한 ASCII 밖·`"`·`\`·`%` 를 `_` 로, `filename*` 은 `encodeURIComponent` + `'()*` 도 인코딩), `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox`, `Cache-Control: no-cache, no-transform`(압축을 꺼 Content-Length·Range 206 이 산다). octet-stream·attachment·CSP sandbox 라 주소를 새 탭으로 열어도 HTML·SVG 가 문서로 그려지지 않고 받기만 된다. `sendFile(dotfiles: 'allow')`. GET 이고 상태를 바꾸지 않아 Origin 은 안 본다. 로그인한 다른 기기도 받는다 (→ security.md)
- **Copy 메뉴 Download** (모든 기기, `isLocal` 무관, Copy file 다음 줄, title "Download <이름>"): `startDownload(downloadUrl(…), 이름)` — 숨긴 `<a href download>` 를 body 에 붙여 누르고 뗀다. 이름은 서버 머리가 정하고 `download` 값도 같은 이름. Changes 의 지운·없어진 파일(`isShownFileGone`)이면 비활성(title "The file is gone from the working copy")
- **Copy 메뉴 Share…** (`window.PrayShare` 가 있을 때만 — 안드로이드 앱 WebView): 누르면 `window.PrayShare.share(url, fileName)` — url = 받기 주소의 **절대 주소**(`absoluteDownloadUrl(location.origin, …)`, 앱은 페이지 밖에서 받아서), fileName = 파일 이름, 둘 다 string, 반환 없음. 지운 파일이면 비활성. **브리지 계약**: 앱이 `addJavascriptInterface(…, "PrayShare")` 로 넣고, url 이 `<지금 PC 출처>/api/sessions/<id>/file/download?path=…` 꼴인지 검사한 뒤 받아서 Android 공유 창을 띄운다 — 주소 꼴을 바꾸면 앱도 같이 고친다 (앱 쪽 → android.md). 메뉴 항목은 FilesTab 을 그릴 때 `shareBridge()` 로 정한다 (브리지는 페이지 시작 전에 들어 있다)

## 확인하지 못한 것
