# 알림 (Reminders)

정한 시각에 **사람에게 한 번** 울리는 알림. 반복은 없고, 팀장·파트장 세션에 메시지를 보내지 않는다 (사람에게만). 등록 경로는 화면 Reminders 창(사람)과 팀장·파트장 MCP 도구 `team_remind` 둘이다. 저장·API·울리기(서버)·화면(목록 툴바 Reminders 줄·창)·MCP 도구·트레이 Windows 알림이 있다. 이 영역을 고치면 이 파일의 그 줄을 고쳐 쓴다.

## 구조

- `host/src/reminder.ts` — 꼴·판정 순수 함수 (`@pray/host/reminder`, 테스트 `reminder.test.ts`). `Reminder { id, text, at, createdAt, createdBy, firedAt, isLate?, acknowledgedAt }`·`ReminderCreator`(`{ kind: 'user' }` 또는 `{ kind: 'lead', teamId, partId, sessionId }` — 리드 세션 ID 는 MCP 가 모르니 서버가 등록 때 지휘 단위의 `leadSessionId` 로 채운다), 시각 검증 `parseReminderAt(value, now)` → `{ at }`(UTC ISO) 또는 `{ error: format·past·too-far }`, 울리기·정리 `fireDue(reminders, now)` → `{ reminders, fired, prunedCount }`(넘긴 배열은 안 바꾼다)
- `host/src/hq.ts` 의 최상위 `reminders` (넣은 순서. 정렬은 화면이 한다) — `listReminders`·`addReminder(text, at, createdBy)`(끝에 넣는다)·`acknowledgeReminder(id, isAcknowledged)`(값이 그대로면 안 쓴다. 없음 `ReminderNotFoundError`, 안 울림 `ReminderNotFiredError`)·`removeReminder(id)`(울렸든 아니든)·`fireDueReminders()`(바뀐 게 없으면 안 쓴다). 옛 파일에 키가 없으면 [] 로 읽고 `readOffice` 결과에 싣는다. 서버만 쓴다 — 호스트는 이 키를 몰라도 `readHq` 가 모르는 키를 보존해 지우지 않는다
- `server/src/index.ts` 의 알림 API·울리기 (아래 핵심 개념)
- `mcp/src/teamServer.ts` 의 **`team_remind`**(옛 모드 `jk_remind`. 모드·등록 방식 → team.md 의 mcp) — 팀장·파트장이 사람에게 알림을 등록한다. 인자 `{ text, at?, inMinutes? }`: at·inMinutes 중 정확히 하나(둘 다·둘 다 없음·0 이하는 서버를 부르지 않고 실패 결과, `reminderAtOf`). `inMinutes` 는 MCP 가 자기 시계로 UTC ISO 로 바꾸고(서버와 같은 PC), `at` 은 다듬어 그대로 넘겨 서버 `parseReminderAt` 가 검증한다 (오프셋 없으면 이 PC 시각). `TeamApi.remind` → `POST /api/team/:teamId/reminders`(파트장은 `?partId=`). 결과 = 서버 응답 `{ reminder }` + `firesAt`(울릴 시각)·`now`(지금 시각) — 둘 다 이 PC 시각 글자 `2026-11-12 15:30 (UTC+09:00)`(`localTimeText`), 리드가 사용자에게 "15:30 에 울린다" 고 확인해 주게. **규칙은 도구 설명 한 곳에만 있다 (lead.ts 지침에는 넣지 않았다)**: "30분 뒤" 는 inMinutes, "15시" 는 at, 지금 시각이 필요하면 셸 date, 알림은 사람에게만 가고 리드를 깨우지 않는다, 취소·목록은 사람이 화면에서, ScheduleWakeup·CronCreate 같은 내장 예약 도구가 아니라 이 도구를 쓴다(그것들은 리드를 깨울 뿐이고 세션이 끝나면 사라진다). 도구 설명은 리드 claude 가 다시 떠야(resume 포함) 반영된다. 테스트 `teamServer.test.ts`·`teamApi.test.ts`
- `web/src/RemindersButton.tsx` — **목록 툴바 "Reminders" 줄과 Reminders 창** (툴바 → toolbar.md). 줄(`RemindersButton`, `.toolbar-row`): New Group 아래·Lead models 위 전체 폭, 알람시계 SVG `currentColor` + 글자 "Reminders" + 오른쪽 끝 배지 = 울렸고 확인 전 개수만 빨강(`.needs-you-count.urgent`). 예정만 있으면 배지 없이 보통, 하나도 없으면 흐리지만(opacity) disabled 아님 (등록하러 들어가야 해서). 누르면 App 의 `isRemindersOpen` 으로 창(`RemindersModal`, `Modal` 제목 "Reminders" + 닫기 ×, Esc·바깥 클릭, 폭 480px·높이가 넘치면 창 안 스크롤, 안 칸은 창 안쪽 여백에 맞춰 좌우 여백을 뺀다)이 뜬다. 사이드바 보기가 아니다 (예전에는 Needs you 처럼 사이드바 보기였다). 창: 맨 위 글 칸 "Remind me about…"(Enter 로도 보냄, 한글 조합 중 무시, `maxLength` 없음 — 길이는 서버) + `<input type="datetime-local">`(min = 지금 분, App 의 1분 시계) + Add(글·시각이 다 있어야 켜짐, 보내는 동안 "Adding…"). 글 칸 Enter 때 시각이 비었으면 시각 칸에 포커스만. 보낼 때 `localInputToIso`(= `new Date(값).toISOString()`, Z 꼴)로 `POST /api/reminders`, 응답 항목을 `applyReminder` 로 App 의 office(`changeReminders`)에 먼저 넣는다 (SSE office 로도 온다). 기다리는 사이 바꾼 칸은 남긴다. "Fired" 구역(있을 때만) = 울렸고 확인 전, `firedAt` 최근순: 체크 = `PATCH {isAcknowledged:true}`(응답을 넣으면 확인한 것이라 숨는다) · 글(두 줄까지, 전문 title) / "Due 14:00"(오늘이면 시각만, 아니면 아래 꼴) · 주의색 "Late"(`isLate`) · 만든 이 · ×(`DELETE`). - **트레이 Windows 알림** (`desktop/src/reminderNotice.ts` 순수 함수, 테스트 `reminderNotice.test.ts`. 띄우기는 `desktop/src/main.ts` 의 `pollReminders`·`notifyReminders`. 세션 알림의 토스트 꼴·그림·클릭·`Notifications` 메뉴 규칙 → host.md "세션 Windows 알림"): 트레이 5초 폴링에서 `/api/sessions` 가 성공하면 `GET /api/reminders` 도 받는다 (못 받거나 404(옛 서버)면 그 회차만 건너뛰고 상태는 그대로). 타입 `NotifyReminder`·`NotifyReminderCreator` 는 서버 `Reminder` 를 손으로 맞춘 사본이다 — desktop 은 dist 를 그대로 실행하는 CommonJS 라 `@pray/host/reminder` 를 require 하지 못한다 (서버 꼴을 고치면 같이 고친다). **알릴 것** `newlyFiredReminders(notifiedIds, notifyFrom, reminders)`: `firedAt ≥ 트레이를 켠 시각(REMINDER_NOTIFY_FROM)` 이고 확인 전이고 아직 알리지 않은 id(메모리 Set `notifiedReminderIds`)만, 넣은 순서대로. 첫 폴링에서 기준만 잡는 세션 알림 방식은 쓰지 않는다 — 트레이가 띄운 서버가 시작하자마자 늦음으로 울린 것(`firedAt` 은 트레이를 켠 뒤)을 놓친다. 켜기 전에 울린 것은 화면 배지로 본다. 고른 것은 띄우기 전에 바로 Set 에 넣고, `Notifications` 를 꺼 뒀으면 띄우지 않고 넣기만 한다 (다시 켤 때 몰아서 뜨지 않게). **창이 앞에 있어도 띄운다** (세션 알림과 달리 화면에는 배지뿐이라). **글자**: 제목 `reminderTitle` = 리드 등록 "[Lead] 이름 · Reminder"(파트장은 `createdBy.partId` 로 "[Part lead]" — 화면 `creatorLabel` 과 같은 규칙, 이름은 `createdBy.sessionId` 세션의 `nameOf`. 세션을 못 찾으면 "[Lead] Reminder"), 사람 등록 "Reminder", `isLate` 면 "Late reminder" / 본문 `fitOneLine(text)` / 회색 줄 `placeLabel`("팀 › 파트", `createdBy.teamId`·`partId` 와 `/api/office`. 사람 등록·못 찾으면 없음). 그림은 등록한 리드 세션의 인물 머리(`reminderSession` → main.ts `sessionFace`), 사람 등록·못 찾음은 Pray 마크, 고리는 `NOTICE_RING_COLORS.reminder`(웹 `--accent` #3f9c4b — 다크 테마도 같은 값이라 Done 고리와 같은 초록). 한 번에 3개(`MAX_SEPARATE_NOTICES`) 넘으면 묶음 "Pray · N reminders" 한 장(`reminderBundleToast` — 본문 `bundleToast` 그대로 줄마다 `reminderBundleLine` "[Lead] 이름 · 글"(사람 등록은 글만)을 자르지 않는다, Pray 마크, 누르면 창만). **누르면** 그때 `/api/office` 를 다시 받아 `reminderTarget`: 그 지휘 단위(팀 직속 = `teams[].leadSessionId`, 파트 = `parts[].leadSessionId`)의 지금 리드 — Hand over 로 등록한 리드가 바뀌었을 수 있다. 지금 리드가 없거나·팀·파트가 없어졌거나·office 를 못 받으면 `createdBy.sessionId`, 그것도 null 이거나 사람 등록이면 창만 연다 (`showNotification` 의 대상이 함수면 누를 때 불러 정한다). 누르기로 확인(`acknowledgedAt`)되지는 않는다 — 확인은 화면 체크

## 핵심 개념

- **꼴.** `id` = `randomUUID` 앞 8자리. `text` = 할 일 글과 같은 규칙(`parseTodoText`: 줄바꿈마다 공백, trim, 1~500자). `at` = UTC ISO(`toISOString`). `firedAt` = 서버가 울린 시각(아직이면 null). `isLate` = 울릴 때 정하는 `firedAt − at > 90초`(`REMINDER_LATE_MS`, 서버가 30초마다 보므로 넉넉히) — 화면·트레이가 같은 값을 읽게 저장한다. 울리기 전에는 키가 없다. `acknowledgedAt` = 사람이 확인한 시각 (boolean 을 따로 두지 않는다 — 보관 기간을 이 시각으로 센다)
- **시각 검증 (`parseReminderAt`).** 받는 꼴 `YYYY-MM-DDTHH:mm[:ss[.sss]][Z|±hh:mm]`. 오프셋이 없으면 **이 PC 시각**(JS `Date.parse` 규칙)이고, 날짜만 있는 꼴은 JS 가 UTC 로 읽어 헷갈려 거절한다. 없는 날짜·시각(2026-02-31·25:00·:60)은 칸을 되짚어 거절(Date 는 넘친 칸을 다음 달로 넘긴다). 1분(`REMINDER_PAST_GRACE_MS`) 넘게 과거면 past(입력하는 사이 지난 몇 초는 받아 다음 회차에 울린다), 366일(`REMINDER_MAX_AHEAD_MS`, 연도 오타 막기) 넘게 뒤면 too-far. 화면은 브라우저에서 `toISOString()` 으로 바꿔 Z 꼴만 보낼 것 (폰 등 다른 시간대 기기에서도 같은 절대 시각)
- **울리기.** 서버가 시작할 때(이전 작업들 뒤) 한 번, 그 뒤 30초마다(`REMINDER_TICK_MS`) `fireReminders()` → `fireDueReminders`: `at ≤ 지금` 이고 안 울린 것에 `firedAt`·`isLate`, **확인한 지 7일(`REMINDER_RETENTION_MS`, 퇴근 기록·task 와 같은 7일) 넘은 것은 지운다** (경계 시각은 남긴다. 확인 전인 것은 지우지 않는다). 그래서 서버가 꺼져 있던 사이 지난 알림은 켜질 때 늦음으로 한 번 울린다. 울린 것이 있으면 `broadcastOffice()`. 요청 처리 밖이라 던지지 않는다 — hq.json 을 못 읽으면 그 회차만 건너뛰고 로그는 실패·복구로 바뀔 때만. 화면 입력이 분 단위라 30초 간격이면 충분하다 (늦어도 30초 안에 울린다)
- **API** (인증·Origin 은 다른 `/api` 와 같다. 오류는 `{ message }` 영어): `GET /api/reminders` → `{ reminders }`(트레이 폴링용. 화면은 `GET /api/office`·`office` SSE 의 최상위 `reminders` 로 받는다) · `POST /api/reminders` `{ text, at }` → `{ reminder }`(사람 등록 `createdBy: user`. 글 400 "Text must be 1 to 500 characters", 시각 400 "Time must be a date and time like …"·"Time must be in the future"·"Time must be within a year") · `PATCH /api/reminders/:reminderId` `{ isAcknowledged }` → `{ reminder }`(boolean 아님 400, 없음 404 "Reminder not found", 안 울림 409 "This reminder hasn't fired yet" — 지우기는 DELETE) · `DELETE /api/reminders/:reminderId` → `{}`(없음 404) · `POST /api/team/:teamId/reminders[?partId=]` `{ text, at }` → `{ reminder }`(MCP `team_remind`. 팀·파트 없음 404 "Team not found"·"Part not found" 이 글·시각 검증보다 먼저, 검증·400 문구는 사람 등록과 같은 `parseReminderBody`. `createdBy: { kind: 'lead', teamId, partId(팀 직속 null), sessionId }` 의 sessionId 는 그 지휘 단위의 지금 `leadSessionId`, 지시자가 없으면 null). 바뀌면 `office` SSE. team_status 에는 싣지 않는다
- 시각은 서버 PC 시계 하나로 본다 (`firedAt` 을 서버가 적어 트레이가 같은 PC 시계로 "켠 뒤 울린 것" 을 고른다 — 위 트레이 Windows 알림)

## 확인하지 못한 것

- 트레이 Windows 알림은 단위 테스트(`reminderNotice.test.ts`)와, 빌드한 desktop 모듈(`reminderNotice`·`toast`·`icon`·`noticeFace`·`dotCharacter`)을 쓰는 Electron 시험 앱(electron dist 사본, 제품 이름 "Pray Reminder Test", ID `pray-reminder-test`, 배율 100%. 끝나고 .lnk·CLSID·알림 설정 키를 지움)으로만 확인했다: 실행 중인 서버(GET 만)의 실제 팀·팀장 세션으로 "[Lead] 이름 · Reminder"·인물 머리·초록 고리·한 줄로 자른 한글 본문·회색 줄 팀 이름, 사람 등록 "Late reminder"·Pray 마크, 묶음 "Pray · 4 reminders"(긴 줄은 접혀 4줄쯤에서 잘림)가 `show` 되고 배너에 보였다(화면 캡처). 실제 트레이(main.ts 의 `pollReminders`·`notifyReminders`)로 알림이 울릴 때 뜨는지, 누를 때 지금 리드 세션 패널이 열리는지(클릭은 사람이 눌러야 한다), `Notifications` 를 끈 동안 울린 것이 다시 켤 때 안 뜨는지는 보지 못했다 (트레이를 다시 띄워야 해서 사용자가 반영한다)
