# 호스트·hq.json·트레이 앱

호스트(named pipe·pty·`hq.json`)와 트레이 앱(Electron)·작업 스케줄러 스크립트·훅 설치 스크립트를 다룬다. 팀 할 일의 저장 규칙(서버 쪽)도 `hq.ts` 에 있어 여기 둔다.

원래 루트 `CLAUDE.md` 한 파일이던 내용을 옮긴 것이다. 본문의 "위·아래 …"·"핵심 개념 …" 은 그때의 말이라 가리키는 항목이 다른 파일에 있을 수 있다. 어디서나 지킬 규칙·근무·휴식·퇴근·표시 상태·실행 방법은 루트 `CLAUDE.md`, 다른 영역은 루트의 문서 지도를 본다. 이 영역을 고치면 이 파일의 그 줄을 고쳐 쓴다.

다른 파일에 있는 항목:
- 핵심 개념 "모델·effort 바꾸기" → server-api.md
- 핵심 개념 "세션 이름은…" → server-api.md
- mod → queue-interrupt.md
- 호스트 쪽 모델·effort 바꾸기(`restart-session`)의 서버 규칙 → server-api.md

## 구조

- `host/src/index.ts` — named pipe `\\.\pipe\pray-host` 서버. **시작할 때 옛 이름의 pipe `\\.\pipe\jk-corp-host`(`LEGACY_PIPE_PATH`)에 connect 해 보고(`legacyHost.ts` `isPipeAlive`: 붙으면 아무것도 보내지 않고 끊는다, 2초 넘으면 없는 것으로) 붙으면 로그를 남기고 종료 코드 0 으로 끝난다** — pipe 이름이 달라 옛·새 호스트가 둘 다 떠서 같은 웹 세션을 두 번 resume 하는 것을 막는 호환 코드. 트레이도 같은 확인을 한다(아래). 연결된 모든 클라이언트에 모든 세션 출력을 보낸다 (구독 관리 없음). `restart` 메시지를 받으면 종료 코드 2 로 나가고 트레이 앱이 다시 띄운다 (0 은 "의도한 중지" 라 안 살린다). `resume` 은 퇴근 기록의 cwd·extraArgs 그대로 `--resume` 한 뒤 기록을 webSessions 로 되돌리고, `forget` 은 퇴근 기록과 이름을 지운 뒤 `sessions` 를 다시 보내 서버가 목록을 다시 읽게 한다. `kill` 에 `isReleased` 가 있으면(팀원 정리) released 퇴근이 된다. `restart-session` `{ sessionId, extraArgs }` 은 근무 중인 웹 세션을 그 인자로 다시 띄운다 (`PtyPool.restart`, 아래 핵심 개념 "모델·effort 바꾸기") — 프로세스·기록이 없거나 kill 로 끝나는 중이거나 hq.json 을 못 쓰면 그 클라이언트에 `error` 만 보내고 아무것도 바꾸지 않는다. 시작 때와 1분마다 보관 기간이 지난 퇴근 기록을 지우고, 지운 것이 있으면 `sessions` 를 다시 보낸다 (hq.json 을 못 읽으면 로그는 실패·복구로 바뀔 때만)
- `host/src/ptyPool.ts` — node-pty로 `claude.exe --session-id <uuid> [첫 지시] ...extraArgs` 실행, 세션별 200KB 링버퍼. `spawn.extraArgs` 로 `--name`·`--permission-mode`·`--mcp-config` 등 추가 인자를 넘기고 `webSessions` 에 같이 저장해 resume 때도 넘긴다. **첫 지시는 extraArgs 앞에 둔다** — `--mcp-config` 는 값을 여러 개 받아서, 뒤에 두면 첫 지시를 설정 파일 이름으로 읽고 claude 가 바로 종료된다(종료 코드 1). claude 경로는 `--claude=` 인자 (스케줄러 환경엔 사용자 PATH 가 없어 설치 스크립트가 넘김). 자식 env(`childEnv`, spawn·resume 모두)에 `CLAUDE_CODE_PLUGIN_DIRS=<저장소 절대 경로>\mod`(`import.meta.dirname` 기준)를 넣어 웹 세션에만 아래 mod 를 불러온다 — `CLAUDE*` 를 지운 뒤에 넣어야 남는다. claude 가 끝나면(onExit) webSessions 기록을 퇴근 기록으로 옮긴다: 이유는 `offDutyReason` — kill 요청이면 그 kill 의 이유(`isReleased` 면 released, 아니면 dismissed. kill 은 종료 코드 1 로 끝나서(실측) 코드로는 못 가린다), 0 이면 exit(`/exit` 는 0), 그 밖은 error. `~/.claude/projects/<프로젝트>/<id>.jsonl` 이 없으면 다시 출근할 수 없어 기록·이름을 지운다(`discardWebSession`). 끝날 때마다 보관 기간 정리도 한다. 프로세스 없이 기록만 남은 세션에 kill 이 오면 바로 그 kill 의 이유로 퇴근시킨다. `restart(sessionId, extraArgs)`(모델·effort 바꾸기)는 webSessions 기록의 extraArgs 를 먼저 바꾸고(`setWebSessionArgs`. 못 바꾸면 던지고 끄지 않는다 — 옛 인자인 채 끄면 다음 호스트가 옛 인자로 resume 한다) claude 를 kill 한다. entry 에 `restartArgs` 가 있으면 onExit 는 퇴근으로 옮기지 않고 같은 폴더·앞 pty 크기(`cols`·`rows` — 화면 터미널 탭은 자기 크기가 바뀌기 전엔 resize 를 다시 보내지 않는다)·새 인자로 바로 `--resume` 한다. 새 프로세스를 먼저 넣고 `exit` 를 알리므로 호스트 목록에서 빠지는 순간이 없고, 서버는 `exit` 로 평소처럼 제안·붙잡은 질문·running task 를 정리한다 (화면 터미널 탭에는 "[Session ended: …]" 뒤에 새 화면이 그려진다). 다시 띄우는 중에 kill 이 오면 kill 이 이기고(퇴근), restart 가 또 오면 기록·인자만 새것으로 바꾼다. 다시 띄우기(spawn)가 던지면 claude 가 오류로 끝난 것과 같게 퇴근 error(종료 코드 null)

- 호스트 자체가 죽으면 웹 세션도 죽는다. 허용한 설계. `hq.json.webSessions` = "호스트가 살려 둘 세션". 호스트가 죽을 때(트레이 kill·재시작 exit)는 pty onExit 가 돌지 않아 기록이 남고(휴식) claude 도 같이 끝난다 (node-pty 로 띄운 실제 claude 는 부모 node 를 강제 종료하면 10초 안에 끝났다. 남으면 다음 호스트가 같은 세션을 또 resume 한다). 다음 호스트가 시작할 때 `--resume` 한다 (폴더가 없으면 건너뛰며 지운다). 호스트가 살아 있는데 claude 가 나가면(exit·오류·kill) 퇴근 기록으로 옮기고, 다시 출근하면 저장된 extraArgs(팀장 지침·`--mcp-config`·권한 모드)가 그대로 넘어간다 — 터미널에서 직접 `claude --resume` 하면 이 인자가 빠진다
- **한 번도 대화하지 않은 세션은 resume 이 안 된다** (jsonl 이 없다. `/exit` 로 끝내도 생기지 않는다(실측)). 그래서 끝날 때 jsonl 이 없으면 퇴근 기록 없이 지운다 (resume 의 "No conversation found" 종료도 여기로 빠진다). 정상
- **팀 할 일 (`teams[].todos`, 서버 쪽).** 배열 순서 = 표시 순서이고 `hq.ts` 가 늘 [할 일(사용자가 정한 순서)…, 완료(완료한 순서, 오래된 것 먼저)…] 로 나눠 둔다: 추가는 할 일 구역 맨 끝(첫 완료 앞), 완료가 되면 doneAt = 지금이고 맨 끝으로, 되돌리면 doneAt null 이고 할 일 구역 맨 끝으로, 완료 값이 그대로면 자리·doneAt 그대로, 순서 바꾸기는 할 일 구역만(완료 구역은 그대로), 완료 전부 삭제 뒤에도 할 일 구역 순서는 그대로. 글은 문자열이고 줄바꿈(`
`·`
`·`
`) 하나마다 공백 하나, 앞뒤 trim, 1~500자(JS 문자열 길이 = UTF-16). ID 는 그룹·팀처럼 `randomUUID` 앞 8자리. 그룹에는 할 일이 없다. 팀을 지우면 그 팀 할 일도 같이 없어진다. 서버가 시작할 때 아래 두 가지를 이 순서로 한 번씩 돌린다 (둘 다 읽을 때 바꾸지 않고 — 할 일 ID 가 읽을 때마다 바뀌지 않게 — 한 번 써서 남기며, 옮길 것이 없으면 쓰지 않고, hq 를 못 읽으면 던져 서버가 로그만 남기고 다음 시작 때 다시 한다):
  - `migrateWaitingNotes`: 예전 그룹 대기 메모(`waitingNote`)를 그룹의 옛 `todos` 로 옮기고 키를 지운다. `- ` 로 시작하면 맨 앞·줄바꿈 뒤·쉼표 뒤의 `- ` 마다 한 항목(항목 끝 쉼표·공백은 뺀다. 항목 안의 ` - ` 는 나누지 않는다), 아니면 글 전체가 한 항목, 빈 메모는 키만 지운다. 옮긴 항목은 미완료·createdAt = 옮긴 시각으로 할 일 구역 끝에 붙는다. 500자 제한은 적용하지 않는다 (예전 메모는 `prompt()` 한 줄이라 짧다)
  - `migrateGroupTodosToTeams`: 그룹의 옛 `todos` 를 팀으로 옮기고 그 그룹의 `todos` 키를 지운다. 그 그룹(`groupId`)의 팀이 하나면 전부(완료 포함, 순서·id·시각 그대로) 그 팀으로. 팀이 여럿이면 글이 `<이름> - ` 로 시작하고(첫 ` - ` 앞이 이름, 뒤가 비면 접두어로 보지 않는다) 그 이름이 팀 이름에 대소문자 무시로 들어 있는 항목은 그 팀으로 옮기며 접두어를 떼고(여러 팀에 맞으면 이름이 가장 짧은 = 가장 비슷한 팀, 같으면 teams 배열에서 앞선 팀), 나머지는 그 그룹의 첫 팀(teams 배열 순서)으로. 팀이 없는 그룹은 옮기지 않고 `todos` 를 그대로 둔다 (결과 `leftBehind`, 서버가 시작할 때마다 로그 한 줄). 받는 팀에는 구역 규칙대로 붙는다 (할 일은 할 일 구역 끝, 완료는 완료 구역 끝). 두 번째부터는 키가 없어 아무것도 안 옮긴다. 빈 `todos: []` 키는 지우려고 쓰지는 않는다

## 확인하지 못한 것

- 옛 호스트 막이는 시험 호스트(임시 홈, 새 pipe 는 가짜 이름)로만 확인했다: 가짜 옛 pipe 를 열어 두면 종료 코드 0·로그 한 줄, 없으면 listen, 옛 pipe 를 돌리지 않으면 실제 트레이 호스트에 붙어(보내지 않음) 종료 코드 0. 트레이의 막이(옛 잠금 실패 창·옛 pipe 확인 창)는 실제 트레이 앱으로 보지 못했다 (실제 앱 데이터 폴더를 건드리고 트레이를 다시 띄워야 해서)
- 설정 폴더 이전(`dataDir`)은 단위 테스트(다섯 상태·파일을 연 자식 프로세스·세 프로세스 동시 경쟁)와 시험 홈(실제 hq.json·instructions.jsonl 사본)에서 호스트 모듈(`setupFileLog`·`hq.ts`)·시험 서버(포트 4797, 가짜 pipe)로만 확인했다. 실제 트레이(Electron)가 실제 `~/.claude/jk-corp/`(sprite-src 353MB 포함)를 옮기는 것은 보지 못했다. 앱 데이터 폴더 이전(`moveAppDataOnce`)은 같은 순서의 Electron 시험 앱으로 옮겨지는 것·옛 인스턴스가 잠금을 쥐면 EPERM → 옛 폴더·잠금 실패를 쟀고, 실제 트레이 main.ts 로 실제 `@jk-corp\desktop`(창 테마·Appearance)을 옮기는 것은 보지 못했다. 이 PC 의 실제 트레이는 `~/.claude/pray/`·`%APPDATA%\@pray\desktop` 을 쓰고 옛 폴더는 없지만, 원래 옛 폴더가 있던 PC 가 아니라 이전 확인은 아니다 (실제 데이터를 옛 자리로 되돌려야 재 볼 수 있어 남긴다)
- 토스트 알림은 같은 `toastXml`·`noticeIconPng`·`noticeFace`(빌드한 desktop 모듈)를 쓰는 Electron 시험 앱(electron dist 사본, 제품 이름 "Pray Face Test", ID `pray-face-test`, 배율 100%)으로만 쟀다: 실행 중인 서버의 아틀라스·실제 세션(고른 인물 + 색, 해시 인물)으로 Done·Needs approval 은 인물 머리·고리 색·제목·한 줄 본문·"팀 › 파트", 묶음은 Pray 마크가 `show` 되고 배너에 보였다(화면 캡처). 그 전 꼴에서 깨진 XML·이스케이프 안 한 제어 문자는 `failed` "Invalid XML". 머리 그림이 화면 목록 아바타와 픽셀까지 같은지는 같은 규칙·같은 함수 결과를 맞춘 단위 테스트로만 봤다 (두 그림을 나란히 비교하지 않았다). 클릭은 사람이 눌러야 해서 재지 못하고 Electron 44.9.1 소스로만 봤다: 토스트 `launch` 클릭은 WinRT Activated → arguments 에 `type=action|reply` 가 없어 `NotificationClicked` → `click`. 이전 꼴(버튼 있던 때) 시험 중 사람이 알림을 한 번 눌러 `click` 이 왔다. 배너가 사라질 때(약 6~9초, 누르지 않음) `close` 가 왔다 — main.ts 는 `close` 에 Notification 을 Set 에서 빼므로 알림 센터에 남은 알림을 나중에 누를 때 객체가 GC 됐으면 `click` 이 안 올 수 있다 (토스트 XML 전부터 있던 동작, 미확인). 실제 트레이(main.ts)로 띄운 토스트·배율 150% 이상의 그림 선명도와 본문 한 줄 폭은 보지 못했다
- 세션 Windows 알림은 단위 테스트(판정·글자)와, 같은 `setAppUserModelId`·`Notification` 코드의 작은 Electron 스크립트(배너가 뜨고 기록에 그 ID 로 남음, 배너를 눌러 `click` 이벤트가 옴), Vite dev + headless Chrome 의 해시 처리로만 확인했다. 실제 트레이(main.ts 전체)로 상태가 바뀔 때 알림이 뜨는지, 알림 클릭 → 창 열기 → 세션 패널, 창이 앞일 때 열린 세션 빼기, `Notifications` 메뉴 저장, 서버·호스트 재시작 뒤 가짜 알림이 안 뜨는지는 보지 못했다. `show` 이벤트가 왔는데 배너가 보이지 않은 것은 시작 메뉴 바로가기가 막 생긴 첫 알림이었다 (위 "세션 Windows 알림". 다른 이유는 미확인). exe 브랜딩(`brand-electron.mts`)은 electron dist 사본에만 해 봤다: 파일 설명·제품 이름 Pray, exe 아이콘 16·32·48·256, 사본으로 띄운 알림 머리 "Pray"·Pray 아이콘(새 시험 ID), 실행 중인 사본에는 경고·종료 코드 0. 실제 exe 는 파일 설명·제품 이름이 Pray 이고 트레이가 그 exe 로 돈다 (읽기만 확인). 바뀐 아이콘(작업 표시줄·바탕화면 바로가기·작업 관리자)과 반영 뒤 ID `pray` 의 알림 머리 이름은 눈으로 보지 못했다 (실제 알림이 떠야 해서). 창 아이콘(.ico 경로) 크기는 배율 100% 화면에서만 쟀다

- 벡터로 그린 아이콘(`icon.ts`)은 단위 테스트와 크기별 PNG 를 뽑아 지금 것과 나란히 본 것까지다. 실제 트레이가 `tray.ico` 에서 배율에 맞는 크기를 고르는지(배율 100% 화면뿐이라 16 만 볼 수 있다), 다시 브랜딩한 exe 의 탐색기·작업 표시줄 모습은 보지 못했다 (트레이 Quit·exe 다시 쓰기가 필요해 사용자가 한다)
