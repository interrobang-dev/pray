# 대화 탭·터미널 탭·작업 파일·Shells

jsonl → 대화 메시지(서버 `messages.ts`)와 화면의 대화 탭(말풍선·작업 묶음·relay 한 줄·작업 중 표시기·입력 상자·첨부·제안·질문 카드), 마크다운, 작업 파일 보기, 백그라운드 shell 보기, 터미널 탭을 다룬다.

원래 루트 `CLAUDE.md` 한 파일이던 내용을 옮긴 것이다. 본문의 "위·아래 …"·"핵심 개념 …" 은 그때의 말이라 가리키는 항목이 다른 파일에 있을 수 있다. 어디서나 지킬 규칙·근무·휴식·퇴근·표시 상태·실행 방법은 루트 `CLAUDE.md`, 다른 영역은 루트의 문서 지도를 본다. 이 영역을 고치면 이 파일의 그 줄을 고쳐 쓴다.

다른 파일에 있는 항목:
- 핵심 개념 "보내기의 함정" → queue-interrupt.md
- "보내기의 함정" → queue-interrupt.md
- 대기 메시지 취소·작업 중지 규칙 → queue-interrupt.md
- AskUserQuestion 붙잡기·답 API → server-api.md
- 점프·돌아가기·Shells 요청의 App 쪽 → web-app.md

## 구조

- `server/src/messages.ts` — jsonl → 채팅 메시지 배열. assistant 는 `message.id` 로 묶고 tool_result 를 tool_use 에 붙인다. **도구 결과는 2000자에서 자르되 `mcp__jk-corp__` 도구 결과는 자르지 않는다** — 팀원 보고가 `jk_wait` 결과 JSON 안에 있어 자르면 화면이 해석하지 못한다 (팀장 세션 응답이 약 20% 커진다). 사람 쪽 글(일반 user·`queued_command` 첨부·대기 enqueue)은 **Claude Code 의 붙여넣기 감싸기를 풀어 보낸 글 그대로 되돌린다**: 감싼 꼴은 `\n\n<pasted_content id="4자리 hex">\n` + 글 + `\n</pasted_content id="같은 id">\n\n` (pty 입력은 4096바이트 조각으로 들어와 붙여넣기로 인식된 조각마다 감싸이고, 경계는 낱말 중간일 수도 있다). 감쌀 때 넣은 줄바꿈(앞뒤 최대 2개, 태그 안쪽 1개)까지 지운다 — Claude Code 자신의 풀기와 같은 규칙이고, 태그만 빼면 원문과 안 맞는다. id 가 4자리 hex 가 아니거나 닫는 태그가 없으면 그대로 둔다. system 판정(`<` 로 시작)은 풀기 전 글로 한다 (붙여 넣은 HTML 이 system 이 되지 않게). **대화 압축 요약**(Claude Code 가 압축 때 `compact_boundary` system 줄 다음에 남기는 `isCompactSummary: true` user 줄)은 사람 말이 아니라 role system + `isCompactSummary: true` 로 내고 글은 원문 그대로다(붙여넣기 풀기 없음. 지시 맞추기·대기열과 무관). **중지 줄**(Esc 로 멈추면 Claude Code 가 남기는 user 글 줄 `[Request interrupted by user]`·`[Request interrupted by user for tool use]`, `interruptedMessageId` 가 붙음)도 사람 말이 아니라 role system + `isInterrupt: true` 로 낸다 (글이 정확히 그 꼴일 때만. 그 글을 인용한 사람 말은 그대로). AskUserQuestion 결과 줄의 `toolUseResult.answers`(`{ 질문문: 답 }`)는 그 도구 호출의 `answers` 로 싣는다 (취소·대화로 답하기는 `toolUseResult` 가 `"Error: …"` 문자열이라 없다). 지시 기록 읽기(`parseInstructionLog`)·맞추기(`attachInstructions`)와 아직 대기 중인 사람 쪽 글 목록(`queuedPrompts`: jsonl content 그대로와 화면 글. 글 없는 enqueue·`<` 로 시작하는 글은 뺀다)도 여기 (순수 함수). **해석은 두 단계다**: 줄 단계 `MessageLineParser`(줄마다 JSON.parse 해 쓰는 것만 남긴 `MessageLine`, 배열 자리 = jsonl 줄 번호. 도구 결과를 자를지는 앞에 나온 도구 호출 이름으로 정하려고 도구 ID → 이름을 들고 있다. `peek` 는 그 상태를 바꾸지 않는다)와 뒷단계 `buildMessages`(결과를 앞 도구 호출에 붙이기·message.id 로 합치기·대기열. 매번 새 객체를 만들고 줄은 바꾸지 않는다). `parseMessages` 는 둘을 이은 것이고, 대화 API 는 덧붙은 줄만 줄 단계에 넣고 뒷단계는 늘 처음부터 다시 한다 (dequeue 짝 찾기 `promptAfter` 가 뒤 줄을 봐서 앞 결과가 뒤 줄에 따라 바뀐다. → server-api.md `messageCache.ts`). 뒷단계가 쓰는 원래 줄의 필드를 늘리면 `MessageLine` 에도 넣어야 한다
- `web/src/Markdown.tsx` — 마크다운 렌더러 `MarkdownText` (react-markdown + remark-gfm. 대화와 작업 파일 미리보기가 같이 쓴다). raw HTML 은 글자로 보인다 (rehype-raw 를 쓰지 않는다 — 글이 페이지에 HTML 을 꽂게 된다). 링크는 새 탭. 문법 강조(rehype-highlight. 색은 highlight.js 테마 CSS 를 불러오지 않고 style.css 의 `.hljs-*` 규칙이 `--hl-*` 변수로 칠해 팔레트·다크를 따른다 → web-app.md 테마)는 **언어가 표시된 코드 블록만** 하고 자동 추측(`detect`)은 끈다 (엉뚱한 언어로 칠해서). highlight.js 는 테마 CSS 때문에 직접 의존성으로 두고 버전을 rehype-highlight 안의 lowlight 와 맞춘다 (어긋나면 두 벌 설치된다). `memo` — 대화를 다시 그릴 때(갱신·펼치기·점프 등) 글이 그대로인 말풍선을 다시 파싱하지 않게. **`pre` 는 `.code-block` 상자로 감싸 오른쪽 위에 복사 버튼**(코드 글자만, 끝 줄바꿈 하나 뗌)을 둔다 — 버튼은 상자에, 가로 스크롤은 안쪽 `pre` 만 해서 스크롤 중에도 제자리이고, `pre` 의 아래 간격은 상자가 가진다. 글자는 react-markdown 이 넘기는 hast `node` 에서 text 를 모아 얻는다 (`codeText.ts` — 문법 강조 span 에 걸리지 않는다). `components` 는 모듈 상수라 memo 가 유지된다. 작업 파일 미리보기도 같은 컴포넌트라 같은 버튼이다 (파일 글은 fence 를 씌워 넘기므로 뗀 줄바꿈은 fence 가 붙인 하나뿐이고 파일 자체의 끝 줄바꿈은 복사에 남는다)
- `web/src/CopyButton.tsx`·`copyText.ts`·`codeText.ts` — 복사 버튼(아이콘만. 겹친 사각형 → 성공 1.5초 ✓ → 실패 ✕, title·aria-label "Copy"·"Copy code"·"Copy command" → "Copied"·"Copy failed")과 클립보드 도우미. 상태는 버튼 안 state 라 대화 전체를 다시 그리지 않고, 클릭은 `preventDefault`·`stopPropagation` 이라 말풍선·details 여닫기·점프를 일으키지 않는다. 쓰는 곳 셋: ① claude 글 말풍선(답변·진행 중 묶음 설명 글·펼친 묶음 안 설명 글)과 팀원 쪽 지시 말풍선(`.msg.relay`)의 위 모서리에 걸친 버튼(복사 = `message.text` 마크다운 원문, 글을 가리지 않는다) ② 코드 블록(Markdown.tsx) ③ `ToolBlock` 의 Bash·PowerShell 줄 — `input.command` 가 문자열일 때만 summary 오른쪽 끝(float)에 두고 command 만 복사. 마우스 기기는 말풍선·코드 블록·도구 줄에 올렸거나 버튼에 포커스가 있을 때만 보이고(성공·실패 표시 중에는 늘 보임), `@media (hover: none)` 은 늘 0.65 로 보이고 32px 로 키운다. **`copyText`: `window.isSecureContext` 이고 `navigator.clipboard.writeText` 가 있으면 그것, 아니면(또는 실패하면) 숨긴 textarea + `document.execCommand('copy')`** — 다른 PC 의 `http://<IP>:4710` 은 secure context 가 아니라 clipboard API 가 없다 (선택·포커스는 복사 뒤 되돌린다). 확인용 클립보드 읽기는 Windows 에서 줄바꿈이 CRLF 로 돌아온다
- `web/src/chatSearch.ts`·`ChatSearchBar.tsx`·`chatSearchPaint.ts` — **대화 탭 안 검색** (세션 하나의 대화. 서버는 그대로 — 이미 받은 messages 로 찾는다). 파일 이름이 `ChatSearch.tsx` 가 아닌 것은 Windows 가 대소문자를 가리지 않아 `./ChatSearch` 가 `chatSearch.ts` 와 겹쳐서다. 열고 닫기는 App 이 정해(→ web-app.md) Chat 에 `isSearchOpen`·`searchFocusId`·`onSearchClose` 로 넘기고, 열려 있으면 `.messages-pane` 안 `.messages` 바로 위에 막대(`.chat-search`: 입력칸 placeholder "Search" · 개수 · ↑ Previous · ↓ Next · × Close. 버튼은 아이콘이고 title·aria-label 이 영어. 사무실 숨기기 넓은 화면에서는 양옆을 `--chat-gutter` 로 대화 열과 맞추고 폰은 전체 폭)이 붙는다. 막대가 생기고 사라지면 대화 높이가 바뀌므로 맨 아래를 보고 있었으면 맨 아래에 둔다. **찾는 규칙**(`chatSearch.ts`, 순수 함수): 대소문자 무시(`toLocaleLowerCase`) 부분 일치, 공백뿐인 검색어는 검색어 없음, 입력은 150ms 디바운스(입력 직후 Enter 는 지금 글로 바로 찾기만 하고 이동하지 않는다). **안 그린 줄(위 "최근 줄만 그린다")의 결과도 개수에 들고, 이동하면 그 줄까지 그려서 간다** (접힌 묶음 안 결과처럼. 칠하기는 그려진 요소만). **결과 단위는 화면의 대상 하나**(말풍선·한 줄·명령 도구 줄)이고 개수 "3/12"(결과 없음 "No results", 검색어 없으면 빈 글)·순서는 화면 순서다. 대상은 Chat 의 `buildSearchTargets` 가 `rows` 에서 만든다(검색을 연 동안만): 사람 쪽 글(대기 중 포함)·claude 글(답변·중간 설명 글 모두)·팀원 쪽 지시 말풍선 글("Instruction from …" 라벨은 뺀다)·system 글, **한 줄로 보이는 것은 화면에 보이는 한 줄 글**(알림 제목·압축 요약 "Conversation compacted · …"·"Stopped"·팀장 쪽 지시/보고 한 줄 "→ Assigned to FEPark · 10:12" 전체 — 이름·역할 칩·시각·라벨 어디든 맞으면 결과), Bash·PowerShell 의 `input.command` 전체. 도구 결과·다른 도구 입력·질문 카드·"Sending" 임시 말풍선은 뺀다. 대상 키는 요소의 `data-jump-key` 와 같다: 말풍선·system 글·알림 줄은 메시지 ID(알림이 여럿인 system 글은 `<ID>:<순번>`), 지시/보고 한 줄은 `relay:…`, 명령 줄은 `tool:<도구 ID>`. 그래서 사람 쪽·system 글·`ToolBlock`(셸 명령만)·`NoticeLine` 에도 `data-jump-key` 가 붙는다. 글은 원문(마크다운 기호 포함) 기준이라 `**굵게**` 처럼 화면에 없는 기호로만 맞는 검색어는 개수에는 들고 칠할 글자가 없다. **상태 소유**: 입력 글·결과·현재 번호는 `ChatSearchBar` 안 state 라 글자를 칠 때 Chat(대화 전체)은 다시 그려지지 않는다. 현재 결과가 바뀔 때만 `onCurrentChange(target, isNavigation)` 로 Chat 에 알리고, Chat 의 `searchCurrentKey`(노란 테두리 `.search-current` — 점프의 2초 `.jump-highlight` 와 달리 검색하는 동안 늘 켜 둔다. `markClasses`)와 `searchScroll`(스크롤)이 바뀐다. **현재 위치**: 새 검색어는 맨 아래(가장 최근) 결과에서 시작한다 (대화는 보통 최근 것을 찾는다). Enter = 다음, Shift+Enter = 이전 (끝에서 처음으로 돈다), 한글 조합 중 Enter 무시, Esc = 닫기(이벤트를 멈춰 패널·모달이 같이 안 닫힌다). 같은 검색어에서 대화가 갱신되면 결과를 다시 계산하고 현재 위치는 같은 키에 남기고(없어졌으면 이전 번호에 가장 가까운 것) **스크롤·펼치기는 하지 않는다**(읽던 자리에서 끌려가지 않게). 사용자가 검색어를 바꾸거나 이동했을 때만(`isNavigation`, `stamp`) 그 결과로 간다: 접힌 끝난 작업 묶음 안이면(`SearchTarget.workKey` = 그 묶음 키. 진행 중 묶음의 설명 글은 접혀 있어도 보여 null, 명령 줄은 늘 묶음) `openWorkKeys` 에 넣어 펼치고, 요소를 가운데로 스크롤하고 `onMessagesScroll` 로 "맨 아래를 보고 있는지"에 반영한다. 닫거나 세션·탭을 바꾸면 칠한 것·테두리·입력 글을 버린다. **칠하기**(`chatSearchPaint.ts`): CSS Custom Highlight API — 화면에 그려진 결과 요소(`[data-jump-key]`)의 텍스트 노드에서 Range 를 만들어 `::highlight(chat-search)`(전체 일치, 옅은 노랑)·`::highlight(chat-search-current)`(현재 결과 안, 진한 노랑·priority 1)로 칠한다 (색은 style.css `--search-match-bg`·`--search-current-bg`·`--search-current-text` 라이트·다크). React DOM 은 건드리지 않고 `CSS.highlights` 가 없으면 칠하기만 건너뛴다. 칠할 글에서 빼는 것: `.result`(도구 결과)·`.queued-label`·`.relay-label`·`summary > code`(도구 이름)·접힌 `details` 안(summary 밖). 다시 칠하는 때: 결과·현재 결과·검색어가 바뀔 때와 `.messages` 의 `childList` 변화(메시지 갱신·묶음 펼침, MutationObserver) 뒤 60ms 모아서 한 번. 작업 중 표시기의 1초 타이머는 글자(characterData)만 바꿔 걸리지 않는다. **여러 줄 명령의 한 줄 요약 밖에서만 맞으면**(예: 3번째 줄) 이동할 때 그 명령 줄 `details` 를 펼쳐 JSON 입력 안의 글자를 칠한다 (사용자가 다시 접은 것을 칠할 때마다 펼치지 않게 이동할 때만)

## 핵심 개념

- **`.messages` 의 flex 기준 크기는 `0px` 이다** (`flex: 1 1 0px`, style.css). `flex: 1` 의 0% 는 세로 flex 안에서 정해지지 않은 높이로 풀려 브라우저가 대화 내용 높이를 재는데, 입력 상자 레이아웃이 바뀔 때마다(글자 하나마다) 긴 대화 전체를 다시 재서 큰 세션은 글자당 레이아웃이 약 35ms 들었다 (2,700 메시지 가짜 대화. 0px 이면 약 3ms). 늘어난 크기는 같다 (작은·큰 대화·검색 막대·폰 폭에서 확인). `flex: 1` 로 되돌리지 않는다
- 터미널 스트림은 `attach` 요청에 호스트가 링버퍼 스냅샷을 한 번 주고(`snapshot` 이벤트, 화면 reset 후 그림), 이후 `output`을 잇는다. 서버만 재시작해도 브라우저가 SSE 재연결하면 같은 경로로 복원된다
